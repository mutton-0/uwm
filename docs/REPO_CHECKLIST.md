# 仓库整理表

一张表把 [REPO_GUIDELINES.md](REPO_GUIDELINES.md) 里对仓库的要求全部列出来。目标只有一个:**一个陌生人只看 README,在一台新机器上能把代码跑起来、把结果复现出来。**

什么时候用:
- 第一次建仓库、提初始化 PR 之前,manager 整体过一遍
- 每次对 main 提 PR 之前,提交人对照自己改动涉及的项过一遍,PR 描述里勾上;manager 审核时也对照这张表
- 准备开源(转 public)之前,"开源前"那几项全部要满足

"什么时候要"一栏的意思:**每个仓库** = 所有仓库都必须;**实车项目 / 有多终端时 / 报了结果时** = 符合条件就必须;**开源前** = 转 public 之前必须;**建议** = 不强制,做了更好。

能机械判断的项(文件是否存在、README 章节、.gitignore、大文件、密钥、绝对路径、软链接、CODEOWNERS 等)可以用脚本自动查,结果里带的编号就是这张表的编号:

```bash
python3 skills/sky-lab-repo-audit/repo_check.py <项目目录>            # 平时
python3 skills/sky-lab-repo-audit/repo_check.py <项目目录> --public   # 准备开源时
```

用 AI 检查和整理时,让它按 [skills/sky-lab-repo-audit/SKILL.md](../skills/sky-lab-repo-audit/SKILL.md) 做。脚本查不了的项(能否跑通、结果复现、实车硬件等)脚本输出的最后会单独列出来。

这张表也可以导入 Google Sheet 逐项打勾:[templates/repo_checklist.csv](../templates/repo_checklist.csv)(Google Sheet → 文件 → 导入 → 上传)。

## 最重要的一条:复刻自测

找一个没参与这个项目的同学,或者自己开一个全新的 conda 环境 / 换一台机器,**只看 README**,从 `git clone` 一直跑到出结果。中间卡住、要去问人、要改代码的地方,就是 README 要补的地方。开源前必须做一次,平时 manager 每月审核前建议做。


## 文件和目录

| # | 检查项 | 具体要求 | 什么时候要 |
|---|---|---|---|
| 1 | README.md | 按 REPO_GUIDELINES 第二节的模板写 | 每个仓库 |
| 2 | 环境文件 | requirements.txt / environment.yml / pyproject.toml,版本用 == 钉死 | 每个仓库 |
| 3 | .gitignore | 第一次提交前就配好,从 templates/.gitignore 复制,再看要不要打开最下面按项目的规则;至少忽略数据、权重、rosbag、视频、日志、.env | 每个仓库 |
| 4 | LICENSE | 默认 MIT;基于 Apache-2.0 项目改的用 Apache-2.0 | 每个仓库 |
| 5 | 目录分层 | 代码、脚本、配置分开放(src/、scripts/、configs/),根目录不堆 .py | 每个仓库 |
| 6 | 自检脚本 | scripts/smoke_test.sh,一条命令检查环境、路径、能否跑一次最小推理 | 建议;开源前必须 |
| 7 | AGENTS.md | 写给 AI 的项目须知(用哪个环境、怎么自检、不能动的文件、已知的坑),旁边放一个只有一行 @AGENTS.md 的 CLAUDE.md。模板见 templates/AGENTS.md | 建议 |

## README 内容

| # | 检查项 | 具体要求 | 什么时候要 |
|---|---|---|---|
| 8 | 一句话说明 | 做什么、给谁用、上下游依赖哪个仓库 | 每个仓库 |
| 9 | 维护人和状态 | 顶部写 manager 和状态(active / 交接中 / archived) | 每个仓库 |
| 10 | 软件环境 | Python / CUDA / ROS 等写具体版本号 | 每个仓库 |
| 11 | 硬件环境 | GPU 型号、显存、驱动版本;不需要 GPU 也写明 | 每个仓库 |
| 12 | 安装 | 能直接复制执行的安装命令 | 每个仓库 |
| 13 | 最小例子 | 一条能直接跑的命令,加上预期输出(文件、打印或截图) | 每个仓库 |
| 14 | 多终端 | 哪些要同时开(并行)、哪些要等上一步(串行),并行的重点标出 | 有多终端时 |
| 15 | 数据、权重、视频 | 写下载链接或存储路径,文件本身不放进仓库 | 每个仓库 |
| 16 | 本机专属路径 | 绕不开的绝对路径逐条列出,注明换机器要改 | 有绝对路径时 |
| 17 | 结果复现 | 关键数字给出命令和随机种子;不能完全复现的给多次运行的分布(箱线图或均值±标准差)和原因 | 报了结果时 |
| 18 | 已知问题 | 写实话,包括没做完的 | 每个仓库 |

## 不能进仓库(包括 git 历史)

| # | 检查项 | 具体要求 | 什么时候要 |
|---|---|---|---|
| 26 | 大文件 | 数据集、权重、rosbag、日志、视频不在仓库里,也不在历史里 | 每个仓库 |
| 27 | 敏感信息 | 密钥、token、密码、内网 IP 不在仓库和历史里(可以用 gitleaks 扫) | 每个仓库 |
| 28 | 访问信息和个人信息 | 车机/服务器的主机名、IP、Tailscale 地址,用的谁的账号,个人邮箱,都不写进仓库;文档里写"连接方式见组内 XX" | 每个仓库 |

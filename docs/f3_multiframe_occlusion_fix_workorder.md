# 工单:F-3 多帧候选遮挡漏洞修复(Alpamayo-R1 / AutoVLA)

> **自主执行授权**,不需要逐步请示,按下面的判据自行决策、自行记录到 amendments.md,完成后写 `results/f3_multiframe_fix_DONE.md`。

## 0. 问题(为什么要做这个工单)

`f3_occlusion_vla.py` 现在对两个多帧候选的遮挡实现是:构造模型真实的多时刻输入窗口,**只把窗口里"最后一帧"(即 `t0`,遮挡目标帧)里的实体区域涂掉,窗口内更早的帧完全不动**。这个设计隐含一个假设:窗口里更早的帧,时间上早于危险实体出现(emergence),所以本来就看不到这个实体,不需要遮。

**这个假设没有被验证过,而且至少对 Alpamayo-R1 已经证实不成立**:
- Alpamayo 的窗口是 `num_frames=4`、`time_step=0.1s`(见 `load_nuscenes.py`),总跨度只有 0.3 秒,取 `[t0-0.3, t0-0.2, t0-0.1, t0]`。
- 抽查 `variants/n1_d2/mining/events_all.jsonl` 的一个真实事件:`t_emergence=724.762`,`t0=725.112`(ghost 帧,即 `x_ghost_frames[0]["t"]`)。`t0-0.3=724.812`,**已经晚于 t_emergence**——即这 4 帧几乎全部落在实体出现之后,前 3 帧大概率仍能看到实体,只遮最后一帧根本没有把实体从模型输入里真正移除。
- 该事件的 `x_ghost_frames` 两条记录(`t=725.112`、`t=725.412`)**都带 bbox**,说明实体在这段时间窗里持续可见,不是一闪而过。
- AutoVLA 的窗口是 4 个 nuScenes 关键帧、间隔 0.5s(`N_TEMPORAL=4`,见 `temporal_paths`),跨度约 1.5s,抽查的这一例 emergence-to-t0 间隔(0.35s)小于关键帧间隔,前面几帧大概率确实在 emergence 之前——但这只是这一例,**没有逐事件验证过**,不能当成普遍成立的前提。

**后果**:如果窗口内更早的帧仍能看到实体,现在的 F-3 必要性检验测的其实是"遮住最后一帧之后,模型还能不能从前几帧的历史里看出这个实体",而不是"实体从输入里完全消失后动作会不会退回基线"——这会系统性地把 R 推向"遮挡不改变动作"(必要性比接近 1、FAIL 或"无基线响应"),不是模型真的对实体不敏感,而是遮挡本身没遮干净。这直接可能影响现有 F-3 结论(尤其是两个 VLA 的),必须先修正、重跑、比较新旧数字,再决定论文怎么写。

**另外一条,不要凭主观假设"哪一帧是决策帧"**:现在代码硬编码用 `x_{cond}_frames[0]["t"]`(或 `["sd_token"]`)当作窗口终点 `t0`,默认这就是模型的"决策时刻"。这个假设本身也要在本工单里顺带核查:这一帧是否总是存在、是否总是有效(比如 `covers()` 预筛已经在过滤"贴近场景末尾、模型的 6.4s 未来轨迹构造不出来"的事件,说明"这一帧不存在/不可用"是真实会发生的情况,不是假设性的)。

## 1. 修复方案

对 Alpamayo-R1、AutoVLA 两个候选,把遮挡从"只遮窗口最后一帧"改成"**对窗口内每一帧独立判断实体是否可见、可见则遮**":

1. 复用挖掘阶段已有的 3D 框到 2D 投影逻辑(单帧遮挡/G1 挖矿时已经在用,不需要重新发明),对窗口内的每一个时间戳,用该时间戳对应的 ego pose + 相机外参,把危险实体的 3D 框重新投影到该帧的图像平面,若投影框在画面内(可见),就用该帧自己的图像均值色涂掉对应区域;若某一帧实体确实不可见(投影出画面外,或被判定为遮挡状态),该帧保持不动即可,不用强行处理。
2. 对照臂(`control_box`)同理:同一个对照框位置,在窗口内每一帧都涂,保持"遮挡范围"这一变量在实体臂和对照臂之间可比。
3. `clean` 臂本来就不含实体,不用改。
4. 遇到"某一帧投影需要的 ego pose / 相机外参缺失"这种边界情况,按现有"跳过该事件、计入 skipped 计数"的纪律处理,不要用近似值硬凑。
5. 顺带核查一下:单帧候选(dd/ltf/ddv2/simlingo)有没有类似的"辅助特征泄漏"风险——目前看到的 `spd(ev)` 只是取 `x_clean_frames` 的自车速度均值(标量,不含视觉信息),这条链路本身不太可能泄漏实体信息,但请在报告里明确写一句核查结论,不要跳过。

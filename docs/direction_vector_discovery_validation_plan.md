# 方向向量发现与效度验证:工作计划

> 范围声明:本计划**只覆盖**"给定一个模型,能否找到一个内部方向,其读数可靠预测/解释该模型的行为(尤其失效行为)"这一件事的发现与验证工作。**不包含**:实车数据采集(见 [madison_ghost_probe_acquisition_protocol.md](madison_ghost_probe_acquisition_protocol.md))、多模型排名/选型评分卡(见 [vla_base_model_selection_protocol.md](vla_base_model_selection_protocol.md))、产品 board.json/HTML 呈现(见 [demo_guide_v3_repe_mainline.md](demo_guide_v3_repe_mainline.md) §4)。
> 文献依据:[interpretability_driven_failure_prediction_review.md](interpretability_driven_failure_prediction_review.md)。
> 承接资产:demo 已跑的 T1(视觉判别式方向,E1 FAIL,几何混淆)、T1-L(语言概念方向 $v_{danger}^{lang}$,与行为解耦)、T1-Q($v_{brake}$,已过 W1 steering 全套)、N1(几何平衡负例 D2a/D2b/D2c,已生成)。

---

## 0. 核心原则(决定了下面每个阶段为什么这样排)

1. **两阶段分工,不可互相替代**:方向候选可以由"网络驱动"(读权重/字典学习,不需要预先设计对比刺激)便宜地生成,但**是否可信只能由"真实数据驱动"的验证决定**——网络驱动方法精确的是"结构标签像不像某个概念",数据驱动验证精确的是"这个方向在真实分布上有没有行为预测力"。两者是产出候选与验收候选的关系,不是二选一。
2. **概念向量 ≠ 行为向量,默认视为两个待测对象**:demo 已有证据($v_{danger}^{lang}$ 在浅层 L*=4,$v_{brake}$ 在深层 L*=22)暗示"定义概念"和"驱动行为"可能住在不同位置。任何新方向都要分别评估它更像哪一种,并显式测两者的夹角/相关,不能默认合一。
3. **术语纪律**:方向提取方式按"数据驱动 vs 数据无关"分类,不用"有监督/无监督"(两者都是 training-free,不涉及重新训练;区别在提取时要不要用到标注/配对数据)。
4. **相关系数报告纪律**:任何合并多个异质子群体算出的相关系数,必须先分组报告再合并——防止生态相关虚增(参见 review 文档里 Embodied Interpretability 图3 的教训)。
5. **轴与实例分离(2026-08-28 补,2026-08-29 更新字母,论文叙事纪律)**:本计划提取的每一个具体方向,都必须标注它是 [vla_base_model_selection_protocol.md](vla_base_model_selection_protocol.md) 通用五轴(**G/F/I/C/D**,2026-08-29 由 R/S/I/C/D 重命名而来,I/C 字母不变、R→G、S→F,理由见选型协议 §1)中哪一个轴的实例化,而不是把方向本身当成研究对象——$v_{hazard}^{clean}$/$v_{hazard}$ = G 轴实例,$v_{brake}$ = F 轴实例,$v_{aggressiveness}$/$v_{risk-proneness}$(B4)= D 轴实例,$v_{domain}$(B6)= I 轴所需输入。任何新场景类型复用同一套轴,不为新场景发明新轴名;轴的数量固定为五个,场景/向量数量可以增长。

## 1. 阶段安排

### Stage A|候选生成:网络驱动,数据无关,可立即并行(低成本)

**A1|CoRL 式权重空间投影**:对目标模型的 FFN value vector(或等价中间权重)逐个投影到词表/动作 token 嵌入空间,筛出语义上邻近目标概念库(危险、刹车、谨慎、行人、遮挡……)的候选方向。产出:候选方向清单,每条标注来源层位、最近邻词/token、投影置信度(cos 相似度)。**不对任何候选做行为断言**,这一步只产出"待验证清单"。

**A2(可选,成本高,视 Stage C 结果决定是否启动)|SAE 字典学习**:在大量 ID+OOD 混合的真实驾驶激活上离线训练一次稀疏字典,得到一组解开叠加(superposition)的候选特征,标记与目标概念库邻近的特征 index。定位:比 A1 更彻底但更贵,只在"单方向反复纠缠解不开"时才启动(见 §3 触发条件)。

### Stage B|候选提取:数据驱动,复用/修复 demo 现有工作

> 以下 B1/B4/B5 均为 **G 或 D 轴**的具体实例化方式,B6 为 **I 轴**所需输入(见 §0 原则5);差异在于对比刺激的来源,不是不同的研究目标。

**B1(全计划最高优先级,建议最先跑,G 轴实例)|重跑修复版 T1**:纯 vision-token 区域池化 + **中性 prompt**(不涉及语言生成)+ N1 已修复的几何平衡负例(D2a/D2b/D2c)。目的:检验一个从未被干净测试过的假设——T1 原版 E1 FAIL 是否单纯因为几何混淆(负例没控好),而不是感知层本身没有危险信号。产出:清白版本的"感知端方向" $v_{hazard}^{clean}$ 及其读取端指标(判别 AUC、置换 selectivity、几何稳健性)。

**B2|复核 $v_{danger}^{lang}$(语言概念方向)**:沿用 T1-L 已有产出,不重跑,只在 Stage C 里参与比较。

**B3|复核 $v_{brake}$(行为定义方向)**:沿用 T1-Q 已有产出,已过 W1 steering 全套,作为本计划的"行为锚"。

**B5|行为结果对比,按严格程度分两档(精炼版 $v_{brake}$ 构造)**:原理与 B3 相同(用真实行为结果而非语言/图像刺激分组),但寻找对比样本的方式按因果推断的方法位阶分两档,**优先用严格档,协变量匹配档仅作降级方案**:

- **B5a(首选,精确匹配配对)**:不做统计协变量调整,直接**挖掘天气/车道/背景一致、但动作结果明显不同的真实事件对**——先用 nuScenes 场景级元数据(天气/昼夜/城市)粗筛,再用预训练视觉编码器算图像相似度在粗筛子集内找近邻,确保配对内画面高度一致;动作结果的"不同"按 B5b 同一套阈值定义(硬刹车/急打方向)。这是精确匹配配对(matched observational pairs)设计,严格程度高于协变量调整——背景被锁死后,配对内的动作差异只能由画面里真正不同的因素(如行人有无)解释,不需要我们预先假设"危险长什么样"。产出方向 = 逐配对隐状态差的均值(或 PCA,沿用 RepE 惯例)。
- **B5b(降级方案,仅在 B5a 配对数量不足以支撑统计功效时启用)**:大样本协变量调整——不按场景类别(A/B/C/D2)分组,改按实际行为结果分组,场景复杂度/时段/基线车速等协变量做事后匹配或回归控制,充分利用已有缓存(Tier-M/N1 已挖数千事件)做大样本均值差。

两档共同要求:①不同类型的危险动作(硬刹车、急打方向)分开定义为独立结果变量,各自提取方向,作为锚点电池(B4)成员,过 H4 独立性审计;②提取时应用 §1.5"用途一"的时间窗口均值池化,而非单帧快照;③注意提取对象是**中间层隐状态/激活**,与"最终动作输出层的 logits"(见 §1.5 附近关于 action expert 最后全连接的讨论)是两回事,不要混用术语。

**B6(I 轴所需输入,此前计划遗漏,2026-08-29 补)|提取 $v_{domain}$**:I 轴核心公式 $\theta_L = \cos(v_{domain}, v_{hazard})$ 依赖 $v_{domain}$,而这根向量**尚未被提取**——它不是"闭环验证缺基础设施"的问题,是**发现阶段本身缺输入数据**:需要 ~200 帧 CARLA 参考帧(来源:SimLingo 官方训练数据抽样,或 CARLA 0.9.15 随手采集,成本为小时级)与现有 nuScenes 帧配对(P1,场景内容不必匹配,只需覆盖同等的天气/场景多样性),按 R 轴同一套均值差/PCA 流程提取。**这一步不做,I 轴(开环和闭环版本都)无法计算**,优先级应高于 Bench2Drive(后者只影响 S 的效度加强,不影响 I 能不能算出来)。

### Stage C|交叉印证:合并 Stage A 与 Stage B 的产出

对 A1(及 A2,若启动)产出的候选方向,分别与 B1($v_{hazard}^{clean}$)、B2($v_{danger}^{lang}$)、B3($v_{brake}$)、B6($v_{domain}$,若已提取)算余弦相似度矩阵——B6 与其余方向的夹角即 I 轴的干涉角读数,是矩阵的直接产出之一,不是额外计算。**独立方法互证的方向优先级最高**(网络驱动 + 数据驱动都指向同一方向,是比任一方法自证更硬的证据)。产出:优先级排序后的验证队列,每条候选标注证据来源(仅结构标签 / 仅数据驱动 / 双重印证)。

### Stage D|操纵端验证:复用现有 steering 机制,新增解析法交叉检验

对 Stage C 优先队列里的每个候选,跑完整 steering 四件套(剂量单调、随机方向对照、特异性检查、termination/recovery——沿用 demo W1/W2 已验证过的协议)。

**新增(仅适用于连续/近线性动作头,如 SimLingo 的 waypoint 头)**:先确认提取层到最终输出层之间是否近似线性(没有很深的非线性)。若是,把候选方向直接投影通过最后线性层的权重矩阵(或对更深架构用 Jacobian 近似),解析算出预期行为效应,与已跑的 α 扫描实测效应方向做一致性检验。一致 ⇒ 该候选的因果地位获得双重确认,且以后同类候选可优先用解析法初筛,省去部分昂贵的经验扫描;不一致 ⇒ 说明线性假设或提取位置有问题,按 W1 已有的"仪器 sanity 排查"纪律处理,不得无限调试。

对无法做解析投影的架构(扩散/flow-matching 动作头,或非线性程度过高),**只用经验 steering,不尝试解析捷径**——这是架构决定的,不是退而求其次。

**Stage D 扩展(2026-08-29 重新设计,与选型协议 §3.5 联动,论文方法论贡献的核心来源)**:上述四件套只验证 F 轴(原 S)的开环因果地位;完整的 G/F/I/C 升级验证设计定义在 [vla_base_model_selection_protocol.md](vla_base_model_selection_protocol.md) §3.5,要点:①**F 的主验证已重新设计为"行动层反事实测试"**——复用 G 的同一套 3DGS/D2 反事实配对,读出对象换成动作而非表征,**不需要 Bench2Drive**,可与本 Stage D 的开环 steering 四件套用同批数据一并跑;②**I 的开环计算**依赖 B6($v_{domain}$ 提取)——这是 Stage B 的缺口,成本低(CARLA 参考帧小时级,或直接用 real↔3DGS,见 B6 说明),优先级高,不做 I 轴完全无法出数;③C 的验证改用主计划伪闭环 PDM 式评分,同样不需要 Bench2Drive。**Bench2Drive 全面降级为可选加强项**(仅用于 F 的闭环持续性二级验证,若做,一次性、小规模即可,不阻塞任何主线步骤)。B6 阻塞的是 Stage C 的完整交叉印证矩阵与 I 轴的全部输出,应优先解决。

### Stage E|效度验收与红线检查

汇总 Stage B/D 的读取+操纵证据,按 demo 已有 E1–E4 判据出最终判定表。强制检查两条红线(缺一不可):

1. **跨分布泛化**:每个候选方向必须在从未参与筛选/提取的 held-out 场景类别上复测,不能只看同分布留出集(参见 review 文档 §4 红线1,LLM 幻觉探测器"训练分布内强、真 OOD 崩"的教训)。
2. **强 ground truth**:效度验证挂真实行为指标(轨迹误差/干预率/碰撞率代理量),不能只挂方向自身的读数自洽,或与模型自身输出耦合的间接指标(参见 review 文档 §4 红线2)。

产出:最终"哪些方向可信、可信程度、各自代表什么概念/行为"的效度报告——这是后续评分卡/board.json 的输入,本计划到此收口。**报告强制包含"可迁移方法论 tip"章节**:每个轴(G/F/I/C)在本计划中的验证过程,提炼一条不依赖鬼探头场景成立的通用设计原则(格式与措辞见选型协议 §3.5 的四条 tip),与数值结果并列呈现——这是论文方法论贡献的直接来源,优先级等同于效度判定表本身,不是可选的总结性文字。

## 1.5 锚点向量电池与时间片段聚合方法论(补充,适用于 Stage B 与 Stage D)

### 锚点向量电池(扩展 Stage B,新增 B4)

**B4(D 轴实例)|行为倾向类锚点(危险性倾向 $v_{risk-proneness}$、激进性倾向 $v_{aggressiveness}$ 等)**:这类不是"看没看到危险"的感知概念,是持续性驾驶风格倾向——对应 RepE 自己区分的 **function(程序性倾向)** 而非 **concept(陈述性概念)**。文献依据:**Persona Vectors**(Anthropic 2025)、**CAA**(Rimsky et al. 2024),均用角色扮演式对比 prompt(如"以谨慎风格驾驶" vs "以激进风格驾驶")提取行为倾向方向。

操作纪律:
- 提取沿用 B2 的 prompt 对比流程,换成角色扮演式风格对比;
- **强制验证,不得走捷径**:提取后必须过 Stage D 完整 steering 四件套 + Stage E 两条红线——T1-L 的教训是语言定义的方向不保证驱动真实行为,"倾向"类锚点同样可能解耦,不能因为提取方式更像行为描述就假设它天然有效;
- **电池独立性审计(ICRL 式)**:命名锚点一旦超过两个(危险探测、紧迫性、安全余量、危险倾向、激进倾向……),必须两两报余弦相似度矩阵,防止它们实为同一根轴换了不同名字。

### 时间片段聚合:两个用途,不要混为一谈

**用途一(提取阶段,稳定方向本身)**:function/倾向类方向的标准做法是对多帧(同一 episode 内)隐状态**均值池化**后再做对比提取,而非单帧——RepE 对 function 的惯例、SAPLMA 概念探针的跨 token 均值降噪均如此。此步骤只提升方向提取的稳定性,**不改变单帧模型对速度/TTC 结构性盲的限制**(Q6 结论不受影响)。

**用途二(验证/诊断阶段,更有价值)**:对同一事件,沿时间轴做多次**独立的单帧推理**(不是让模型看多帧,是我们在不同时刻各取一帧分别单独推理),把方向投影值记为随时间变化的**轨迹**而非单一标量。这不会让模型"感知到"速度(每次推理仍是独立单帧、仍对速度结构性盲),但为诊断提供新信号:**投影轨迹的斜率/趋势本身可作为一个新的危险度量**,是把 demo S1 观察性剂量-响应曲线(行为 b vs 距离分箱,demo_guide §4.5)平移到表征层,新增"投影值 vs 距离分箱"曲线——两条曲线趋势一致,是"感知→动作"因果链条的额外交叉印证;对单帧模型而言,这是绕开 Q6 限制、间接捕捉"场景正在恶化"信息的可行路径。

**统计纪律(强制)**:同一事件的多个时间片段高度相关,**不是独立样本**——延续主计划 A.8 纪律,所有 bootstrap/显著性检验以 event/scene 为重采样单位,不得把多帧当独立样本使用(demo 短间隔混淆的教训根源即此)。

## 2.5 泛化性证明(论文叙事要求,与选型协议 §6 验收0 联动)

本计划所有提取工作若只在鬼探头一种场景上验证,不足以支撑"通用轴"的论文主张。**在 Stage E 收口前,补一次轻量级第二场景类型复现**(复用现有 nuScenes 挖掘管线,只换触发判据,如"前车急刹"或"无保护左转冲突"),对该场景重跑 G 轴(B1 同法)与 D 轴(B4 同法)的提取与读取端验证,不要求达到鬼探头同等完整度(不需要 B5/B6/Stage D 全套)。目的仅为回答:同一套轴定义、同一套提取方法,换一个触发条件是否依然给出自洽结果。这是选型协议 §6 验收0(公开榜单 vs 本框架 vs 真实结果三线对比)成立的前提之一。

## 4. 优先级与依赖关系

```
Stage B1(重跑修复版T1)──┐
Stage B6(v_domain 提取)─┼──→ Stage C(交叉印证,含 I 轴干涉角)──→ Stage D(操纵验证)──→ Stage E(效度验收)
Stage A1(权重投影)──────┤
Stage B2/B3(已有,复用)─┘

Stage A2(SAE,可选)只在 Stage C 后仍有"单方向纠缠解不开"时插入,重新进入 Stage C
```

- **Stage B1 与 Stage B6 是两个"不需要任何新方法就该先做"的步骤**,建议并列排最前:B1 成本最低(复用现有缓存,半天到一天),直接检验假设 H1;B6 成本同样低(采集 CARLA 参考帧为小时级),但**不做 I 轴完全算不出来**,优先级不应低于 B1;
- **Stage A1 可与 B1/B6 并行**,三者互不依赖,都是低成本;
- Stage C/D/E 依次依赖前一阶段产出,不可跳步;**Stage C 若在 B6 未完成前执行,只能产出 R/S/C 三轴交叉印证,I 轴留空,须在报告中显式标注而非静默跳过**;
- Stage A2 是唯一的条件触发项,不预先排期;
- Bench2Drive(F 闭环持续性测试,§3.5 已降为可选加强项)不在此依赖图内,可与 Stage D 主线并行、可延后甚至不做,不影响 Stage C/D/E 主链推进。

## 0. 直接结论：漏洞真实存在且比工单估计的更广，但在本样本上没有改变任何判定

| 问题 | 结论 |
| --- | --- |
| 漏洞是否真实存在？ | **是，且两个候选都受影响** |
| 影响面有多大？ | Alpamayo **396/396 帧**（100%）本该遮而未遮；AutoVLA **409/476 帧**（86%） |
| 修复后判定有没有变？ | **没有。两个候选都仍是「不可估：基线响应本身与 0 不可区分」** |
| 那是不是白修了？ | **不是。** 修复触及的是 $b_{occ}$，而这两格的判定门是 $b_{ghost}$（未遮挡臂）—— 修复**按构造不可能**改变它们。若这两个候选存在基线响应，$R$ 就会被系统性地测错。这是一个**当前样本恰好不暴露的正确性缺陷**，不是无害的。 |

**工单对 AutoVLA 的估计需要更正**：工单按 `t_emergence` 推断"AutoVLA 前几帧大概率在 emergence 之前，
因而看不到实体"。**逐帧投影实测否定了这一点**——AutoVLA 窗口 4 帧里平均有 **3.44 帧**能投影出实体，
85/119 个事件是 4 帧全可见。原因是 **`t_emergence` 是"进入走廊 / TTC 越阈"的时刻，不是"变得可见"的时刻**：
行人在进入走廊之前往往已经在人行道上清晰可见。
**"早于 emergence" ≠ "看不见"**，这条本身值得记进纪律（§FM/A57）。

## 1. 修复内容

**旧实现**：构造模型真实的多时刻输入窗口，只把窗口**最后一帧**（$t_0$）里实体的框涂掉，更早的帧完全不动。

**新实现**（`scripts/f3_window_boxes.py` + `f3_occlusion_vla.py`）：
对窗口内**每一个时间戳**独立判断实体是否可见、可见则遮。

* **投影逻辑复用挖掘期的，一行未改**：`g1_mine_events.compute_scene_geometry` + `frame_bbox`。
  两个 VLA 取的都是**真实存在的 nuScenes CAM_FRONT 图像**（Alpamayo 走最近邻、AutoVLA 走 sample 的 prev 链），
  而挖掘期的网格正是该 scene 的全部 CAM_FRONT 帧，故"窗口时间戳 → 网格下标"是**精确匹配而非插值**；
  偏差超过 60 ms 一律判失败并计数（实测 `frames_off_grid` = 0）。
* **每帧用该帧自己的均值色填充**，不是用 $t_0$ 帧的均值色。
* **某帧实体确实不可见就不动**（投影出画幅 / 深度为负 / 该帧无标注），不外推、不近似，计入 `frames_no_box`。
* **对照臂同样逐帧涂**同一个对照框，保证"遮挡帧数"这一变量在实体臂与对照臂之间可比。
* **新增守卫**：若某事件窗口内**一帧都没投影出实体**，该事件的 occ 臂等于什么都没做，
  记 `occ_no_frame_hit` 并**剔除出统计**（实测两个候选都为 0）。
* Alpamayo 的两路前视（120° 广角与 30° 长焦，`camera_indices` 排序后是第 1、3 行）**逐帧都遮**。

**逐帧投影统计（实测）**：

| 候选 | 窗口帧总数 | 可见并遮挡 | 确实不可见 | 时间戳对不上 | 每事件实际遮挡帧数 |
| --- | --- | --- | --- | --- | --- |
| Alpamayo-R1 | 396 | **396 (100%)** | 0 | 0 | 均值 **4.00**（99 个事件全是 4 帧） |
| AutoVLA | 476 | **409 (86%)** | 67 | 0 | 均值 **3.44**（4 帧 85 例 / 3 帧 14 / 2 帧 7 / 1 帧 13） |

**即旧实现下：Alpamayo 每个事件有 3 帧、AutoVLA 平均有 2.44 帧仍然看得见危险实体。**

**判定：两个候选修复前后完全一致，都是「不可估：基线响应本身与 0 不可区分」。**

### 2.1 为什么判定不可能变（这一点要说清楚，否则会误读成"漏洞无害"）

三态判定的门是 $b_{ghost}$：**必要性检验的前提是先有一个响应**。
而 $b_{ghost}$ 是**未遮挡臂**（clean vs ghost），**修复完全不触及它**。
两个候选的 $b_{ghost}$ CI 都跨 0 ⇒ 判定卡在这一步，$R$ 根本不参与判定。

**所以"判定没变"不能读成"漏洞无害"**，只能读成
**"这两个候选恰好在更前面的一道门就被拦住了，漏洞影响的那一段没被用到"**。
若它们像 LTF 那样存在基线响应，$R$ 就会被系统性地测错。

### 2.2 修复确实改动了遮挡臂，且改动量远超运行间噪声

$b_{ghost}$ 按构造不该受修复影响，**它的实测非零量正好是一条现成的运行间噪声地板**：

| 候选 | $\Delta b_{ghost}$（噪声地板） | $\Delta b_{occ}$（修复效应） | 比值 |
| --- | --- | --- | --- |
| Alpamayo-R1 | 非零 **0/99**，\|Δ\| 均值 **0.0000** | 非零 **99/99**，\|Δ\| 均值 **0.1144**（最大 1.497） | **∞**（噪声地板为 0） |
| AutoVLA | 非零 3/119，\|Δ\| 均值 0.0012 | 非零 24/119，\|Δ\| 均值 **0.0196**（最大 0.271） | **16.3×** |

* **Alpamayo 的噪声地板严格为 0**（协议把两条件与全部 patch 运行锁在同一 seed 上，§CE/A39），
  故 $\Delta b_{occ}$ 的 99/99 非零**全部**是修复的真实效应。
* **AutoVLA 有一条很小的噪声地板**（3/119 事件的 $b_{ghost}$ 变了，最大 0.103）：
  它的解码是 `temperature=1e-4 + top_k=1`，**接近但不是**比特级确定性，
  运行间的浮点差异偶尔会翻掉一个 token。修复效应仍是它的 **16 倍**，故不被噪声淹没。
  这条噪声地板此前没有被量化过，本轮顺带得到，已记入 §FM/A58。

**$R$ 的点估计发生了实质位移**（Alpamayo +0.028 → −0.033；AutoVLA −0.590 → −0.433），
但两者的 CI 都很宽且跨 0.5，即便判定门放开也仍是不可估。

## 3. 顺带核查：单帧候选有没有类似的泄漏（工单 §1.5）

| 候选 | 辅助输入 | 是否构成泄漏 | 结论 |
| --- | --- | --- | --- |
| SimLingo / DD / LTF | `spd(ev)` = `x_clean_frames` 的自车速度均值 | **否** | 标量、来自 **clean** 侧、不含任何视觉信息，且三个条件臂共用同一个值 ⇒ 不携带实体信息 |
| SimLingo / DD / LTF | 图像 | **否** | 单帧模型只吃一张图，遮挡即完全移除，不存在"历史帧"通道 |
| **DiffusionDriveV2** | **真实 lidar 点云**（`lidar.ego_points(sd_token)`） | **是，且尚未修复** | 见下 |

**DiffusionDriveV2 存在一条同性质但不同通道的泄漏**：
F-3 的遮挡只涂 **RGB 图像**，而 DDv2 同时吃 ghost 帧的**真实激光点云**（§CE/A29、§CE/A33 要求必须喂真实 lidar）。
**行人在点云里仍然完整存在**，所以对 DDv2 而言"遮挡"从未把实体从输入里移除，只是把它从相机里移除。

**当前影响**：DDv2 的 F-3 判定是"不可估：无基线响应"（三个语料一致），
与 Alpamayo/AutoVLA 同理，卡在 $b_{ghost}$ 这道门上，故**当前结论不受影响**。
**但这是一个与本工单同性质的正确性缺陷，必须登记**（§FM/A58）：
正确做法是同时把点云里落在该 3D 框内的点删掉（或替换为地面点），
本工单范围只涵盖多帧遮挡，未做此项，列入未完成项。

## A.1 修复内容（两臂对称）

* **occ 臂**：删掉落在实体 **ego 系 3D 框**内的点。3D 框与 RGB 侧的 2D 框**同源**——
  同一个 `p_ego` 中心、同一个 `_size`、同一条按最近关键帧取的朝向，
  故"删点"与"涂框"作用在同一个物理实体上，不是两套独立近似。
* **ctrl 臂**：删掉落在**镜像 3D 框**内的点（沿 ego 纵轴 $y \to -y$、$yaw \to -yaw$）。
  体积严格相等、纵向距离相同 —— 与 RGB 侧对照框的**水平镜像**是同一几何构造。
  **不是只删 occ 臂**，否则"删除范围"这个变量在两臂间不可比。
* **外扩 margin = 0.25 m**（各轴）。**这不是为了多删点调出来的**：
  nuScenes 标注/标定误差约 0.1~0.3 m，实测有点落在框外 5 cm 处；
  2D 侧的 `bbox_to_tokens` 本来也已外扩 1 token。**margin = 0.0 作为敏感性口径并列报告。**

## A.3 修复效应 vs 噪声地板

$b_{ghost}$ 按构造不受影响，其非零量即运行间噪声地板：

| 口径 | $\Delta b_{ghost}$（噪声地板） | $\Delta b_{occ}$（堵 lidar 的效应） | $b_{occ}$ 完全没变的事件 |
| --- | --- | --- | --- |
| m = 0.25 | **0/282 非零，均值 0.0000** | 104/282 非零，均值 **+0.0051 [−0.0036, +0.0145]** | **178/282**（框内本来就没有点） |
| m = 0.00 | 0/282 非零，均值 0.0000 | 68/282 非零，均值 +0.0046 [−0.0028, +0.0131] | 214/282 |

* **DDv2 是三个 F-3 候选里唯一比特级确定性的**（噪声地板严格为 0，无采样解码）；
* **但 $\Delta b_{occ}$ 的 CI 跨 0** ⇒ 堵上 lidar 通道带来的行为变化**与 0 不可区分**。

## A.4 为什么效应这么小：实体本来就几乎不在点云里

| 量 | 值 |
| --- | --- |
| 实体纵向距离分位（10/25/50/75/90） | 17.3 / 20.8 / **27.1** / 39.0 / 49.4 m |
| occ 臂删点数（m = 0.25） | 均值 **6.2**，**中位 1** |
| ctrl 臂删点数（m = 0.25） | 均值 4.0，中位 0 |
| occ 臂删点数（m = 0.00） | 均值 2.1，中位 0 |

nuScenes 是 32 线激光雷达，A 类正例的 VRU 中位距离 **27 m**，
在该距离上一个行人的回波只有个位数点、常常一个也没有。
**所以"lidar 泄漏"这条缺陷在本语料上的实际暴露面远小于我上一轮的断言。**

**但修复本身仍然必要**，理由与多帧那次相同：
① 它是正确性问题，不该依赖"这个语料恰好点很少"这个偶然事实；
② 若换到近距事件、更高线数的传感器（如 NAVSIM/OpenScene 的 MergedPointCloud），
暴露面会立刻变大；③ 现在两臂对称，读数含义是干净的。

## A.5 一处必须写明的不完全匹配

**"删除范围"在两臂之间只是同量级，不是相等**：
occ 臂均值 6.2 / 中位 1，ctrl 臂均值 4.0 / 中位 0（m = 0.25）。
镜像体积虽与实体框严格等体积、等纵距，但它常常落在**空旷路面**上，那里本来就没有点。

**处理**：如实报告两臂的删点分布，**不去为了凑数而挑选删点数匹配的对照位置**——
那会让对照框的位置由"点云密度"决定，反而引入新的选择偏差。
当前口径下 $\Delta b_{occ}$ 与 $\Delta b_{ctrl}$ 都与 0 不可区分，这一不完全匹配不影响结论。

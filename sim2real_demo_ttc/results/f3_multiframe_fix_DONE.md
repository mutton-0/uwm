## 1. 直接结论

| 问题 | 答案 |
| --- | --- |
| 漏洞真实存在吗？ | **是，且两个候选都受影响**（工单只确认了 Alpamayo） |
| 漏了多少？ | Alpamayo **396/396 帧（100%）** 本该遮而未遮；AutoVLA **409/476（86%）** |
| 修复后判定变了吗？ | **没变。** 两个候选都仍是「不可估：基线响应本身与 0 不可区分」 |
| 白修了吗？ | **没有。** 判定门是 $b_{ghost}$（未遮挡臂），修复**按构造不可能**改变它；这是"当前样本恰好不暴露"的正确性缺陷，不是无害 |

**工单对 AutoVLA 的估计被实测更正**（§FM/A57）：工单按 `t_emergence` 推断 AutoVLA 不受影响（0%），
逐帧投影实测是 **86% 的窗口帧仍能看见实体**。原因是 `t_emergence` 标记的是
"进入走廊 / TTC 越阈"，**不是"变得可见"**——行人在进入走廊前往往已在人行道上清晰可见。
**"早于 emergence" ≠ "看不见"**，已升为纪律。

## 2. 修复内容

`scripts/f3_window_boxes.py`（新增）+ `scripts/f3_occlusion_vla.py`（改）：
对窗口内**每个时间戳**独立投影实体、可见则用**该帧自己的**均值色遮挡。

* 投影**复用挖掘期的 `compute_scene_geometry` + `frame_bbox`，一行未改**；
* 时间戳 → 网格下标是**精确匹配**（两个 VLA 吃的都是真实 nuScenes CAM_FRONT 图像），
  偏差 > 60 ms 判失败并计数（实测为 0）；
* 某帧确实不可见就不动，**不外推、不近似**，计入 `frames_no_box`；
* **对照臂逐帧涂同一对照框**，保证遮挡帧数在两臂间可比；
* 新增守卫：窗口内一帧都没投影出实体的事件剔除并计数（实测两候选均为 0）；
* Alpamayo 的两路前视（120° / 30°）逐帧都遮。

## 7. 追加：DDv2 的 lidar 通道遮挡（§FM/A59，本轮补做）

**修复**：涂 RGB 的同时删掉落在实体 ego 系 3D 框内的点云点；
**对照臂对称删镜像 3D 框内的点**（$y \to -y$、$yaw \to -yaw$，体积严格相等、纵距相同），
保证"删除范围"在两臂之间可比。margin = 0.25 m（依据标注/标定误差，非为多删点而调），
margin = 0.0 并列为敏感性口径。

| 口径 | $b_{ghost}$ | $b_{occ}$ | 判定 |
| --- | --- | --- | --- |
| 仅 RGB（旧） | −0.1803 [−0.3487, +0.0032] | −0.2060 [−0.3707, −0.0290] | 不可估（无基线响应） |
| **+lidar m=0.25（主）** | **−0.1803 [−0.3487, +0.0032]** | −0.2009 [−0.3658, −0.0256] | **不可估（无基线响应）** |
| +lidar m=0.00（敏感性） | −0.1803 [−0.3487, +0.0032] | −0.2014 [−0.3659, −0.0256] | 不可估（无基线响应） |

**判定三个口径一致、$b_{ghost}$ 一位没变**（按构造不受影响）。
$\Delta b_{occ}$ = **+0.0051 [−0.0036, +0.0145]**，**CI 跨 0** ⇒ 效应与 0 不可区分；
DDv2 的噪声地板严格为 0（0/282，无采样解码），故这不是被噪声淹没。

**一条对上一轮自己说法的更正**：§FM/A58 写的"行人在点云里仍完整存在"**说过头了**。
实测 A 类 VRU 中位纵距 **27.1 m**、nuScenes 为 32 线雷达 ⇒
框内**中位只有 1 个点**、**42% 的事件一个点都没有**（178/282 个事件的 $b_{occ}$ 一位没变）。
准确表述：泄漏真实存在，但在 G1 这份语料上暴露面很小。

**两臂删点数只是同量级不是相等**（occ 均值 6.2/中位 1，ctrl 均值 4.0/中位 0），
因镜像体积常落在空旷路面。**不为凑数挑选删点数匹配的对照位置**（会让位置由点云密度决定）。

新结果另存 `f3_occlusion_ddv2_lidar.json` / `_m0.json`，**旧文件 `f3_occlusion_ddv2.json` 保留**。

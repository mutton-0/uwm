## 0. 核心问题的直接回答

> G1 上测出的两条结论，能不能在另外两个语料上复现？

| 结论 | 复现情况 | 判定 |
| --- | --- | --- |
| **LTF 的 F-3 FAIL**（blind action 签名） | NAVSIM 上**复现**（R = +0.008 [−0.068, +0.078]，b_ghost −0.0249 vs G1 −0.0245）；前车急刹上**无从检验**（基线响应消失） | ✅ **在可检验的语料上复现** |
| **DiffusionDrive 高 G-VS 选择性 + 零 F-3 响应** | 「零 F-3 响应」**3/3 复现**；「高 G-VS 选择性」**1/3**（仅 G1 PASS，另两个语料判不可估） | ⚠️ **一半复现，一半不复现** |

**并且必须先写在最前面的一条**：本轮发现 G-VS 存在一个**此前未暴露的方法学问题**——
在 NAVSIM 语料上，`position_only` 地板（只用 token 坐标）**超过了** trained mIoU
（DDv2 0.371 vs 0.355；SimLingo 0.411 vs 0.408）。
即**一个只知道"这个 token 在画面什么位置"的平凡基线，比基于表征的探针还准**。
selectivity 是对 `random_init` 的配对差，故仍可为正；
但"selectivity PASS"**不等于**"表征比知道坐标更有用"。详见 §3。

**我们没有因为 G-VS/F-3 是本文新提出的"更客观"的轴就放松标准**：
三态判定、两条必需对照臂、scene 级 bootstrap 全部照旧，
"没有基线响应"与"FAIL"仍然分开报。上面这条不利发现正是照旧执行的结果。

### 1.1 LTF 的 FAIL 在 NAVSIM 上复现得很干净

| 量 | G1 | NAVSIM |
| --- | --- | --- |
| $b_{ghost}$ | −0.0245 [−0.0384, −0.0102] | **−0.0249 [−0.0399, −0.0099]** |
| $R$（必要性比） | +0.113 [+0.044, +0.191] | **+0.008 [−0.068, +0.078]** |
| $R_{ctrl}$（涂别处） | +0.029 [−0.031, +0.081] | −0.033 [−0.132, +0.054] |
| 判定 | **FAIL** | **FAIL** |

$b_{ghost}$ 几乎逐位相同（−0.0245 vs −0.0249），$R$ 的 CI 上界都远低于 0.5，
ctrl 臂两边都落在 0 附近。**这是本工作线里少见的"点估计与判定同时复现"的一格。**
NAVSIM 上的 $R$ 甚至更低（+0.008，即遮住危险实体几乎移除不了任何响应）。

**前车急刹上无从检验**：LTF 的 $b_{ghost}$ 掉到 −0.0068（CI 跨 0）。
按既有纪律这判"不可估：基线响应本身不存在"，**不判 FAIL**。
这与该语料上 F①、G 轴全线不可估是一致的（见 `second_scenario_generality_report_*`）。

### 1.2 "无基线响应"是全表最稳的读数

DiffusionDrive **3/3**、DiffusionDriveV2 **3/3**、Alpamayo-R1 **2/2**、AutoVLA **2/2**
的 $b_{ghost}$ 在所有测过的语料上都与 0 不可区分。
**即"这四个候选的规划速度对危险帧没有可检测的响应"这件事，跨场景、跨数据源都成立。**

这条负面结论的稳健性**高于本文任何一条正面结论**，值得单独记下。

### 1.3 ctrl 对照臂在三个语料上都行为正常

全部 16 格的 $R_{ctrl}$（能算的）都落在 0 附近、CI 跨 0，
即"在别处涂同样大小的灰斑"从不让动作退回基线。
**这是 LTF 两次 FAIL 判定得以成立的前提**，两个新语料上都成立。

## 2. G-VS：点估计复现，判定不复现

**Table 2. G-VS selectivity = mIoU(trained) − mIoU(random_init)，三语料对比。**

| 候选 | G1 | 前车急刹 | NAVSIM | 点估计跨度 | 判定序列 |
| --- | --- | --- | --- | --- | --- |
| **SimLingo** | **+0.0273 [+0.013, +0.042] PASS** | **+0.0397 [+0.021, +0.059] PASS** | **+0.0350 [+0.019, +0.050] PASS** | 0.027 ~ 0.040 | **PASS ×3** |
| DiffusionDrive | **+0.0381 [+0.021, +0.055] PASS** | +0.0281 [−0.002, +0.058] 不可估 | +0.0171 [−0.000, +0.034] 不可估 | 0.017 ~ 0.038 | PASS → 不可估 → 不可估 |
| LTF | +0.0191 [−0.001, +0.038] 不可估 | +0.0209 [−0.007, +0.048] 不可估 | **+0.0239 [+0.007, +0.041] PASS** | 0.019 ~ 0.024 | 不可估 → 不可估 → PASS |
| DiffusionDriveV2 | +0.0159 [−0.003, +0.035] 不可估 | **+0.0409 [+0.007, +0.078] PASS** | **+0.0193 [+0.001, +0.037] PASS** | 0.016 ~ 0.041 | 不可估 → PASS → PASS |

**这张表要分两层读，结论不同**：

* **点估计层面：复现得相当好。** 12 格 selectivity 全部落在 **[+0.016, +0.041]** 这个窄带里，
  没有一格变号、没有一格塌到 0 附近。这与老 G 轴形成鲜明对比——
  老 G 轴的 LTF 阳性从 +0.070 掉到 +0.011（NAVSIM），点估计本身塌了。
* **判定层面：不复现。** 四个候选里只有 SimLingo 三次都 PASS；
  另外三个的 PASS/不可估 判定在语料间来回翻。
  原因是**效应量（0.016 ~ 0.041）与 CI 半宽（0.015 ~ 0.035）同量级**，
  判定落在 CI 是否恰好压住 0 这个边界上。

**准确表述**：G-VS 的**读数**跨场景跨数据源稳定，但**在当前样本量与探针设置下，
三态判定不稳定**。这不是"新轴也不可靠"，而是"新轴的效应量小到需要更大样本或更强读出才能稳定判定"。
下一版的直接可行改进见 §4。

## 3. 一个此前未暴露的问题：position_only 地板在 NAVSIM 上超过了 trained

**Table 3. 三条臂的绝对 mIoU。`position_only` 只用 token 的 (row, col) 坐标。**

| 候选 | 语料 | trained | random_init | **position_only** |
| --- | --- | --- | --- | --- |
| SimLingo | G1 / LB | 0.396 / 0.406 | 0.369 / 0.366 | 0.356 / 0.337 |
| SimLingo | **NAVSIM** | 0.4075 | 0.3725 | **0.4108 ← 高于 trained** |
| DiffusionDrive | G1 / LB / NS | 0.382 / 0.387 / 0.384 | 0.344 / 0.359 / 0.367 | 0.333 / 0.331 / 0.371 |
| LTF | G1 / LB / NS | 0.367 / 0.371 / 0.384 | 0.348 / 0.350 / 0.360 | 0.333 / 0.331 / 0.371 |
| DiffusionDriveV2 | G1 / LB | 0.348 / 0.366 | 0.332 / 0.325 | 0.333 / 0.331 |
| DiffusionDriveV2 | **NAVSIM** | 0.3551 | 0.3358 | **0.3711 ← 高于 trained** |

**NAVSIM 上 `position_only` 地板从 0.33 升到 0.371**，两格超过了 trained mIoU。

**为什么**：NAVSIM 的相机是 1920×1080、主点 (960, 560)，4:1 裁剪带覆盖的画面构图与 nuScenes 不同，
物体在画幅内的位置分布更规律 ⇒ 仅凭 token 坐标就能猜得更准。
这是**语料属性**，不是模型属性。

**后果，必须写明**：
1. **selectivity（对 random_init 的配对差）仍然有效**——它控制的是"探针容量 + 空间先验"这两项，
   两臂共享同一套 token 坐标，故坐标先验在配对差里被抵消。四格 PASS 判定不受影响。
2. **但"G-VS PASS"不能读成"表征比知道坐标更有用"**。在 NAVSIM 上，对 SimLingo 与 DDv2 而言，
   一个平凡的坐标基线在绝对 mIoU 上就赢过了表征探针。
3. **因此 G-VS 当前只支持"表征里含有超出随机初始化的物体性信息"这一较弱的主张**，
   不支持"表征提供了实用的物体定位能力"这一较强的主张。

**这条不利发现是照旧执行判定纪律的直接结果**：若当初只报 selectivity 不报 position_only 臂，
本轮就不会暴露它。**两条必需对照臂里，这一条这次比 random_init 更有信息量。**

## 4. 与老 G/F 的稳健性对比（工单要求的核心比较）

**Table 4. 三个语料上的复现率，新轴 vs 老轴。**

| 轴 | 跨场景（前车急刹） | 跨数据源（NAVSIM） | 性质 |
| --- | --- | --- | --- |
| 老 G（主读数 − D2cV 地板） | **0/3 复现** | **0/4 复现**（含唯一阳性 LTF，功效相当） | **点估计塌陷**（LTF +0.070 → +0.011） |
| 老 F①（b-AUC） | 0/3 | 1/4（仅 SimLingo 逐位复现） | 两个 PASS 全掉 |
| 老 C-hazard | **6/6** | **8/8** | 架构级规律，最稳 |
| **新 G-VS** | 判定 1/4；**点估计 4/4 落在窄带** | 判定 2/4；**点估计 4/4 落在窄带** | **点估计稳，判定不稳** |
| **新 F-3** | 无从检验 ×6（基线响应全消失） | **LTF FAIL 复现**；"无基线响应" 3/3 复现 | **可检验时复现；负面结论最稳** |

**三条结论**：

1. **新轴比老 G/F 稳，但没有 C-hazard 稳。**
   老 G 的点估计会塌（+0.070 → +0.011），新 G-VS 的点估计不塌（全部在 [0.016, 0.041]）。
   但新 G-VS 的三态判定仍会翻，达不到 C-hazard 那种 8/8 的水平。
2. **F-3 在"有基线响应"的前提成立时复现得很好**（LTF 的 FAIL 两次都成立，$b_{ghost}$ 几乎同值），
   但这个前提**本身跨语料不稳**：SimLingo 与 LTF 在前车急刹上都失去了基线响应。
   **F-3 的可测性依赖于候选在该语料上有响应，这是它的结构性限制。**
3. **最稳的读数是负面的**：四个候选"对危险帧没有可检测响应"这件事 3/3、3/3、2/2、2/2 全部复现。
   本工作线里稳健性最高的结论，至此仍然是负面结论。

## 5. 局限

1. **G-VS 仍只覆盖 4/6 候选**（两个 VLA 的 video token 布局未接完，§GF/A50），三个语料都如此。
2. **G-VS 的效应量与 CI 半宽同量级**，判定处在边界上。可行改进：更细的 token 网格
   （现为 TransFuser 系 8×32，一个 token 约 50×50 px）、更多事件、或多层特征拼接。
   **本轮未做这些改进**——改了就不是"换个语料重跑"了。
3. **前车急刹语料的 F-3 只有 90 个可用事件**（LB 正例 103，扣掉无对照框的），
   n 比另两个语料小 3~4 倍，"无基线响应"在该语料上部分可归于功效。
   但注意 DiffusionDrive / DDv2 在 n=282、372 的语料上同样无基线响应，故这条不是纯功效问题。
4. **Alpamayo-R1 / AutoVLA 在 NAVSIM 上未测（n/a）**：它们的适配器分别依赖 nuScenes devkit
   与 nuScenes `sd_token`，NAVSIM 数据不是这个格式。这是**语料侧接口缺失**，非模型侧不可测。
5. **只做了 A/LB 正例类**，B/C 类未测。

### PV.2b 新增登记：提及×刹车的**几何控制**口径（跑数前补登）

**动机**：「提及」与目标成像几何强相关 —— 小集实测 提及子集的成像面积中位 5672 vs 未提及 2932 px
（MWU p=1.1e-5）、纵向距离 21.5 vs 28.7 m（p=1.1e-6）。而**大目标本身也更容易因纯几何原因触发减速**。
因此 2×2 的任何跳升都可能是**几何在两头同时使劲**，而非"感知门控了行为"。

**登记口径（冻结）**：
1. 主检验：提及 vs 未提及的达标率差（Fisher）——同 P3；
2. **控几何后重检**：以 `log10(area_px)` 与 `ecc` 为协变量做 logistic
   （因变量 = b 达标；自变量 = 提及 + 两个几何协变量），看**提及项的系数**是否仍显著；
   并列做**几何分层**版本（面积三分位内分别算差值，复用 Q3 的 caliper 机器）；
3. **读法（冻结）**：
   - 控几何后关联**仍显著** ⇒ 可读作 **「感知门控行为」**；
   - 控完**消失** ⇒ 读作 **「几何共因」**，不得再宣称感知门控。

**适用范围**：几何协变量只有 n1_d2 那轮挖掘存了（`area_px` / `ecc`），
**V-A（tier_m）无几何字段，故几何控制只在 V-BC 上做**；V-A 只报未控版本并注明。

### PV.2c 两种结局的处方含义（**跑数前写死，不许事后挑**）

| 大集结果 | 读作 | 病灶 | post-train 处方 |

## FA.1 设计偏离登记（执行前已知，不静默处理）

**偏离 1 —— T-I 的 3DGS 反事实场景集（P3）在本仓库内不存在。**
全盘检索未发现 3DGS 重建资产（`/data/zihao/HUGSIM` 只有渲染器代码，无本项目场景）。
**替代方案**：使用 `ghosthead_v1` 已有的**同几何双渲染配对**——

（都是 do(appearance)，几何/actor/ego-GT 全部锁死）。

**代价与声明**：这不是 3DGS 重建，因此 I 轴结论的适用范围写作"CARLA 渲染 ↔ 世界模型真实感渲染"，

**偏离 2 —— T-F 的回归目标"真实 a_brake"在事件账本里没有现成字段。**
`events_all.jsonl` 只存了逐帧 `ego_speed_mps`（clean/ghost 各 2 帧）。
**处理**：回到 nuScenes ego_pose 重算每个事件在 $[t_{emergence}, t_{emergence}+3\,\mathrm{s}]$ 窗口内的
真实自车纵向加速度序列，取该窗口最小值（最强减速）为 $a_{brake}$（单位 m/s²，负值为减速）。
这是**人类驾驶员的真实行为**，构成 Stage E 红线 2 要求的强 ground truth，而不是模型自身输出的代理量。

## DV/A12 峰层选择规则修正(跑数中途,已对两条臂同步应用)

**问题**:原规则"取 4 折各自嵌套选层 argmax 的**众数**"在平局时退化为"取层号最小者"。
CARLA 臂实测峰层为 `[8, 8, 0, 0]`,2-2 平局 ⇒ 规则给出 L*=0(第 0 层,几乎不可能是概念峰层)。

**修正**:改为**逐折 S_sel 层剖面(AUC-by-layer)的均值取 argmax**。该规则无平局退化,
且用满了每折的全部层信息而非只用 argmax 一个点。**对 nuScenes 与 CARLA 两条臂同步应用**,
不是只在结果不好看的那条臂上改。修正后:CARLA L*=8(与众数 8/8 一致),nuScenes L*=9(与原众数一致)。
两条臂的众数值一并落盘为 `peak_layer_mode_sensitivity`。

**影响**:只影响冻结方向的读出层(Stage C/D 用),不影响 CV 读数本身(CV 的选层始终在折内嵌套完成)。

## DV/A14 Stage C 多重比较零分布的修正(把命中数从 11 改成 0)

**问题**:首版 Stage C 用 3000 个随机抽样的 value vector 估零分布,再用**高斯尾**
(Bonferroni z·sd)外推阈值。实测该零分布尾部远重于高斯 —— 经验 q99.9 = 0.100~0.154,
而高斯尾给出的阈值只有 0.071~0.084,即**阈值比零分布自己的千分位还低**。
按这个偏松的阈值,190×5=950 个格子里有 **11 条**"双重印证"。

**修正**:改用**全总体枚举**做零分布 —— 24×4864 = 116,736 个 value vector 全部参与
(扣掉 190 条候选本身,余 116,546),每个 unit 与各轴在**自己的层**上算 |cos|。
α = 0.05/950 = 5.3e-5 对应总体第 ~6 名,可直接取经验分位,**不需要任何分布假设**。
按修正后的阈值,双重印证 **0 条**,H2 **不成立**。

**这条修正把一个阳性结果改成了阴性结果**,是本轮唯一一处方向性反转,故单独立条记录。
两版阈值与全部余弦值均落盘于 `cosine_matrix.json`(`gauss_bonferroni_REJECTED` 字段
保留被否决的旧阈值以便复核)。

**方法学教训(将写入 generalizable_tips.md)**:在"N 个候选取 max"的场景里,
用观测量的方差 + 高斯尾外推极值阈值是不安全的——权重空间的余弦分布尾部显著重于高斯;
只要候选总体是可枚举的,就应当直接枚举总体取经验分位,而不是外推。

## DV/A15 Stage C 余弦基的修正(RMSNorm 基 -> 残差流原始基)

**问题**:A1 给 value vector 打概念分时,必须先过最终 RMSNorm 再乘输出嵌入(logit lens 的定义)。
首版 Stage C 沿用了这个 **RMSNorm 后的基**去和数据驱动方向算余弦。
但 `v_hazard_clean`/`v_brake`/`v_domain` 都是在**逐层原始隐状态**上拟合出来的,
两者不在同一个基里,余弦的几何含义不成立。

**修正**:Stage C 主口径改为**残差流原始基**(FFN value vector 未经 RMSNorm 直接单位化 ——
FFN 本来就是把它按系数写进残差流的),RMSNorm 基版本作为敏感性并列(`--basis rmsnorm`,`_rmsnorm` 后缀)。
两个基下 H2 的结论一致(双重印证均为 0 条),故本修正不改变判定,只修正几何依据。

## DV/A16 证伪地板的口径修正(把 T-G 的 H1 判定从"成立"改回"不可估")

**问题**:项目既有口径(`n1_cv.py`,`n1_report.md` 已发表的数字)是——

## DV/A17 Stage E 红线 1 的泄漏修正（held-out 必须正负两侧都干净）

**问题**：首版红线 1 把"从未参与拟合的**正例类别**"当作 held-out（B、C），

## HL/A22 轮询脚本自匹配 bug（用户发现，记入自我更正记录）

**现象**：本轮用 `until ! pgrep -f "<pattern>" >/dev/null; do sleep N; done` 等待后台 GPU 作业退出时，
两个等待任务永远不返回。GPU 早已空闲、被等的计算早已完成并落盘。

**根因**：`pgrep -f` 匹配的是**整条命令行**，而轮询循环自身的命令行里就包含那个 pattern 字符串
（`bash -c 'until ! pgrep -f "scripts/t2_steer.py.*dvnull" ...'`），于是 pgrep 匹配到轮询进程自己 ⇒
条件恒为真 ⇒ 死等。同一个坑还出现在 `pgrep -f "tag _dvq_cand1_L22"` 那一次。

**代价**：没有丢失任何计算，也没有产生错误结果，**只浪费了几个小时的等待**。
两个僵死的等待任务已确认杀掉。

**下次的做法（三选一，按可靠性排序）**：
1. **等 PID 而不是等模式**：`until [ ! -e /proc/<PID> ]; do sleep N; done`（本轮后半程改用此法，有效）；
2. **等产出物而不是等进程**：`until [ -f <output.json> ]; do sleep N; done`（最稳，且顺带确认作业真的成功）；
3. 必须用 pgrep 时，**加进程名过滤并排除自身**：
   `pgrep -f -x ... ` 或 `pgrep --ns $$ -f ... | grep -v $$`，或让 pattern 不出现在轮询命令行里
   （把 pattern 写进一个变量文件，轮询脚本读文件）。
**一般化教训**：任何"按命令行文本搜索进程"的轮询，都必须先问一句"这个 pattern 会不会匹配到我自己"。

## HL/A24 C 轴 top-2 占比公式的适用性判据（SimLingo 上前提不成立）

**发现**：给 SimLingo 补测 C 轴后，其逐层恢复剖面是**从 L0 单调递减到 L23**
（1.004 → 0.000，Spearman(层号, recovery) = **−0.997**, p = 1.3e-26），
而 DiffusionDrive 的剖面是**内部峰**（L0/L1 近 0，峰在 L6，Spearman **+0.881**）。

协议 §3⑤ 的 $C_m$ = top-2 层 recovery 占比，其**隐含前提是剖面存在内部峰**。
剖面单调递减时（"级联"签名：失效在最前端就已进入、patch 越早恢复越多），
top-2 占比量到的只是"1/L 的某个倍数"，**不构成集中度证据**。
SimLingo 的 $C_m$ = 0.176（弥散基线 0.083）若照字面读会得到"PASS：失效集中"，**这是误读**。

**修正**：新增 `scripts/c_axis_shape.py`，对两个模型统一计算三个与层数无关的形状量并写回各自 JSON：
① Spearman(层号, recovery)；② 达到 80% 恢复质量所需层数占比；③ 责任层 argmax 的归一化熵。
并加**适用性判据**：ρ < −0.7 判定为级联 ⇒ top-2 公式不适用，C 判 **不可估（公式前提不成立）**，
实质结论改述为「失效在视觉输入接口即已进入并向下游级联」。
DiffusionDrive（ρ = +0.881）不受影响，仍判 PASS。

**连带纪律**：$C_m$ 的弥散基线随层数变化（8 层 0.250 vs 24 层 0.083），
**跨模型不可直接比较 $C_m$ 数值**；可比的是上述三个形状量。已写入三线表的可比性列。

## HL/A25 DiffusionDrive 的 F 轴 steering 仪器无分辨力（含站内上界标定与剂量升级）

1. **注入确实到达了模型**：横向偏移随 α **单调且对称**变化（α=+0.5→+4：−0.0002 → −0.0022 m；
   负向镜像），舒适度亦然。故不是钩子/返回值没生效。
2. **站内上界标定失败**：另造 $v_{brake}^{dd}$（用 DiffusionDrive **自身** commanded_speed 对 ego 速度
   回归后的残差二分作标签，逐层判别，held-out AUC 0.656 @L5，与 SimLingo 的 $v_{brake}$ 同构）。
   按构造它必然与行为相关，但注入它的全阶梯斜率仍只有 **+0.00002 [−0.00013, +0.00021]**，
   同样未超随机零分布。**连按构造必然有效的轴都推不动 ⇒ 该仪器在此标本上无分辨力。**
3. **剂量升级到 ±32σ 仍无效**：α ∈ {4,8,16,32} 下 Δv 最大仅 **−0.0020 [−0.0123, +0.0055]** m/s，
   而同一注入下横向已达 −0.0203 m（α=+32 时 |Δ横向|/|Δv| = 9.96）。不存在阈值效应。

**结论与影响**：DiffusionDrive 的纵向规划输出由 anchored 扩散头（20 个 k-means 轨迹锚）主导，
表征层扰动在测试剂量内不改变锚的选择 ⇒ **F 轴以 steering 效应量操作化时，在两类动作头之间不同量纲，
不得同表排序**。这不是"通路断裂"的证据，而是"该操作化方式不可移植"的证据。
故三线表中 F 轴的 steering 行标注为**不可比**，F 的跨模型对齐改用协议 §3.5 指定的
**行动层反事实测试**（读出对象是动作、不依赖动作头形式，架构中立），两模型均已跑。

## HL/A26 pilot post-train 的设计决策与仪器侧限定（原工单缺失，以下为自行决策）

原工单文件不在磁盘（见 HL/A23），以下设计由我按项目一贯纪律自行决定，逐条登记：

**① 训练预算：只训 `speed_wps_head`（229k 参数），其余全部冻结。**
理由不是省算力，而是这**恰好是选型协议 §1 核心假设的直接检验**——
"内部已编码危险的候选，post-train 只需把读出接到动作上 ⇒ 便宜"。
头之前全部冻结 ⇒ 每个样本的输入特征是常量 ⇒ 一遍前向缓存后离线训练，
整个 pilot 的 GPU 成本 = 2296 次前向。

**② 耦合项的形式：$\\lambda\\cdot\\mathrm{ReLU}(\\Delta_{1\\sigma} + m)$，其中
$\\Delta_{1\\sigma} = v_{cmd}(f + 1\\sigma\\hat v_{hazard}) - v_{cmd}(f)$，margin $m$ = 0.05 m/s。**
关键选择：$\\Delta_{1\\sigma}$ **就是 steering 实验测的 α=+1 剂量响应本身**，不是另造的代理量 ——
"修的量"与"验的量"必须同源，否则"耦合被改变"无法与 steering 读数对齐。

**③ 三臂而非两臂**：必须有 **A1（λ=0，纯任务微调）** 这条归因对照。
事后证明这条对照是决定性的：A2−A0 的行为分增量 = **+0.051**，看起来像成功；
但 A1−A0 = **+0.050**，A2−A1 = **+0.001 [−0.004, +0.007]** ⇒
**行为分的改善几乎全部来自任务微调，与耦合项无关**。
若只跑 A0/A2 两臂，本轮会得出"诊断被验证"的错误结论——这正是用户预先点名要防的误判。

**④ 行为分用三个并列读数，不用单一指标**：
b-AUC(A vs D2a)（held-out scene）、MAE(v_cmd, 人类速度)、ρ(b, 人类真实 a_brake)。
三者在 A1 与 A2 之间**全部持平**（0.592/0.593；0.671/0.673；+0.160/+0.162），结论不依赖指标选择。

**⑤ 仪器侧限定（必须与结论并列陈述）**：耦合所指向的方向 $v_{hazard}$@L23
在 held-out（ghost 条件，n=628）上对真实 $a_{brake}$ 残差的 ρ = **+0.053（p = 0.183）**——
符号正确但**未达显著**。α 由 train 内 scene 级 GroupKFold 选定（α=100，train CV r = +0.008），
未看 held-out。故本 pilot 的准确表述是：
**"把动作耦合到一条只在弱信号意义上读出危险的方向上，耦合量被大幅改变，但行为分没有增量收益。"**
不能表述为"把动作接到危险读出上没用"——后者要求耦合目标本身先通过显著性检验。
首版曾用 pooled（clean+ghost）样本、固定 α=1e3 拟合该方向，held-out ρ = −0.028（**符号还是反的**）；
改为只用 ghost 条件（与 T-F 预注册条件一致）+ train 内 GroupKFold 选 α 后，符号转正。
两版数字均落盘于 `p2_pilot_posttrain.json` 的运行记录，此处如实登记该次修正。

**⑥ 一条附带发现**：纯任务微调（A1）**本身就把耦合量改动了一部分**
（Δcos = −0.061，占 A2 全部改动 −0.113 的 54%）——即"照着人类真实减速去拟合动作头"
会自动带来部分通路连接。耦合项把它再推远一倍（−0.113），**却没有换来任何额外行为收益**。
⇒ **耦合强度与行为分是可解离的**：在本预算下，F 轴耦合不是该行为指标的约束瓶颈。

## CE/A28 TransFuser 与 LTF 的关系：本仓库条件下**同一候选**，不单列

## CE/A29 DiffusionDriveV2 需要真实 lidar：现场构造 nuScenes BEV 直方图（适配偏离声明）

**事实**：DiffusionDriveV2 的两份官方配置（`diffusiondrivev2_{sel,rl}_agent.yaml`）都写 **`latent: False`**；

**处理**：按"每个候选走自己的原生输入格式"这一适配器哲学（SimLingo 走它的裁剪+patch 化，

## CE/A31 **对上一轮 §HL/A25 推论的更正**：注入法不可测是**编码器**属性，不是动作头属性

**上一轮的推论（现予更正）**：§HL/A25 观察到 DiffusionDrive 的 F② 注入法在 ±32σ 内推不动纵向输出，
并把原因归到它的 **anchored 扩散头**（20 个 k-means 轨迹锚），
进而在论文正文 §4.4.2 写下推论"F 轴以注入效应量操作化时**不可跨动作头族比较**"。

**本轮的受控证据**：LTF 与 DiffusionDrive **共用同一个 `TransfuserBackbone(latent=True)` 编码器**，
只在动作头上不同（LTF = 单 trajectory query 过 MLP 的**连续回归头**）。
若上述归因成立，LTF 应当可测。**实测不可测**：

| 注入方向 | 注入层 | ±α 全阶梯斜率 [m/s per σ] | 95% CI | 同层随机零分布 | z | 超出？ |
| --- | --- | --- | --- | --- | --- | --- |
| $v_{hazard}^{ltf}$ | L6 | +0.00040 | [−0.00065, +0.00143] | +0.00019 ± 0.00088 (20 seed) | +0.24 | 否 |
| **$v_{brake}^{ltf}$（站内上界，held-out AUC 0.684@L5）** | L5 | **−0.00004** | [−0.00011, +0.00001] | −0.00000 ± 0.00005 (5 seed) | −0.76 | **否** |

**更正后的归因**：注入法的可测性由**编码器/注入位点**决定，不由动作头决定。
SimLingo（ViT + LLM 残差流，注入 driving query 位置）可测且可被解析 Jacobian 独立复现；
**TransFuser 系编码器（DiffusionDrive 与 LTF 两种动作头都一样）不可测**。
一个合理但**本轮未验证**的机制假说：TransFuser 的融合 token 经
`_bev_downscale` + BEV 上采样 + transformer decoder 的 cross-attention 之后，
σ 尺度的 token 级扰动被稀释；真正的瓶颈在注入位点与动作之间的通路，而非动作头形式。

**影响**：`paper_experiments_section_{zh,en}.md` §4.4.2 的推论句必须改写为
"不可跨**编码器**族比较"，并把 LTF 这一受控对照作为证据补进去。三线表中 F② 行的
"不可比"标注不变，但理由从"动作头不同"改为"编码器不同"。

## CE/A34 **D2cV 证伪地板对多帧候选不成立** —— 这一列必须按输入时序性分组读

**发现**：D2cV 的设计理由是——它与正例**同类别（VRU）、同成像几何，唯一差异是相对速度**，
而**单帧模型对目标运动结构性全盲**（q_audit §Q6），因此任何"A 优于 D2cV"的判别力都不可能来自危险本身，
只能来自泄漏。这条推理**只对单帧模型成立**。

本轮扩池后，候选里出现了**多帧输入**的模型：

| 候选 | 输入时序性 | D2cV 是否仍是证伪地板 |
| --- | --- | --- |
| SimLingo / DiffusionDrive / LTF / DiffusionDriveV2 | **单帧** | ✅ 是 |
| Alpamayo-R1 | 多帧（1.6 s ego 运动史 + 多时刻图像） | ❌ **否** |
| AutoVLA | 多帧（每相机 4 帧时序窗口） | ❌ **否** |

对多帧模型而言，D2cV 与 A 的差异（相对速度）**是物理可观测的**，
"A vs D2cV 显著" 因此是一个**正当的判别任务**，不是泄漏警报。

**处理**：
1. 矩阵中 G 轴"主读数 − D2cV 地板"这一行，**只对单帧候选可读作证伪检验**；
   多帧候选的同一格改标注为 **"D2cV 不适用为地板（多帧可观测速度）"**，并改用
   **标签置换零分布 + 随机方向地板**作为其可用的地板，同时报 A vs D2a 的主读数本身。
2. 这不影响本轮任何已得结论：LTF（单帧）的 G 轴阳性仍以 D2cV 为地板得出；
   Alpamayo 的 G 轴按新规则改报。
3. 该分组纪律写进论文正文的 Setup 与 Limitations。

**为什么现在才发现**：前三轮的候选恰好全是单帧模型，这条前提一直成立且从未被触发。
扩池把它暴露出来——这正是扩候选池在方法学上的价值之一，不只是多几行数字。

## CE/A35 AutoVLA 的环境解法（transformers 版本 × torchvision 算子注册的双重约束）

AutoVLA 接入卡在一个**双重约束**上，两条单独看都无解，合起来才有解，记录如下以便复现：

1. **权重按 `transformers==4.49.0` 的模块布局保存**（`vlm.visual.*`）。
   本机唯一自带 Qwen2.5-VL 支持的环境是 Alpamayo 的 venv（**4.57.1**），
   而 4.57 把视觉塔挪到了 `vlm.model.visual.*` ⇒ 直接加载得到
   **824 missing / 824 unexpected**，即**一个权重都没加载上**（模型能跑，但输出无意义）。
2. **把 4.49.0 装进隔离 target 目录并置于 sys.path 最前**后，导入立刻失败：
   `operator torchvision::nms does not exist` ——
   4.49 的 `qwen2_5_vl` 模块在导入期触发 torchvision C++ 算子查找，
   而此时 torchvision 尚未由那份匹配的 0.23.0+cu128 完成注册。

**解法（写进 `autovla_adapter._bootstrap()`，顺序不可换）**：
venv 上 path → **先 `import torchvision, torchvision.ops`**（用匹配的那份注册算子）
→ 再把隔离的 transformers 4.49 插到 sys.path 最前 → 最后插仓库根。

## CE/A37 「LTF 域不变性优于 DiffusionDrive」是峰层条件结论，不是层不变结论

**读数**：$I_m$（各自概念峰层）LTF 0.583（L6）vs DiffusionDrive 0.203（L5），
scene 级 bootstrap CI 不重叠 → PASS。二者共用同一 `TransfuserBackbone` 架构（权重不同）。

**自检**：因为 $L^*$ 不同，必须做同层对照，否则无法排除「排序只是选层造成的」。
逐层 $D_L$（vision_mean）：

| L | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| DiffusionDrive | 0.033 | 0.001 | 0.667 | 0.056 | 0.633 | **0.797** | 0.730 | 0.956 |
| LTF | 0.156 | 0.004 | 0.777 | 0.362 | 0.679 | 0.672 | **0.417** | 0.588 |

**结论**：只有 L5–L7 是 LTF 更低，L0–L4 全部反号。故该排序**只在各自峰层上成立**，
不能读作「整条编码器都更不变」。已写入 `results/i_axis_domain.json`
的 `same_encoder_layer_matched_check` 字段，并在论文 §4.2.5 标注为条件结论。

**这条本身是结果**：同一编码器**架构**的两套权重，域敏感性沿深度的**分布形状**都不同，
说明 I 轴读数不是架构属性而是权重属性——这正好回答了「换个 ckpt 还算不算同一个候选」
这个在 §CE/A28（TransFuser≡LTF）里以另一个方向出现过的问题。

## CE/A38 AutoVLA 的 G 读数随语料规模移动 —— 折分配噪声，不是新证据

**发生了什么**：AutoVLA 的 G 轴先在只缓存了 A + D2a（574 事件）时跑过一遍，
得主读数 **0.629** [0.584, 0.675]、$\rho(\text{投影}, \log\text{area}) = +0.121$（$p$ = 0.004）。
补齐 D2b / D2c / D2cV（再 538 个事件）后重跑，得 **0.608** [0.562, 0.654]、
$\rho = +0.045$（$p$ = 0.28）。

**为什么会动**：主读数只用 A vs D2a 拟合方向（共享方向地板约定），A 与 D2a 的样本一个没变，
但 **scene 级 CV 的折分配是按语料里出现的 scene 集合生成的**，语料变大 ⇒ 折边界变 ⇒
折内拟合的方向与选出的峰层随之微动。

**如何判定**：两个值都落在 10 seed 折分配稳定性检验的范围内
（主读数 0.588 ± 0.022，范围 [0.55, 0.63]）。**故这是折分配噪声，不是新证据。**
以全量语料的一次为终稿，并在报告里并列写出首版数字与差异原因。

**这条为什么值得单独登记**：如果只跑第一版，我们会在论文里写下
"AutoVLA 的判别方向与成像面积显著相关（$p$ = 0.004），语义纯度低"——
这是一句**会被后续读者当作发现**的话，而它实际上是折分配噪声。
10 seed 折分配稳定性检验不是走过场的稳健性附录，它在这里直接决定了一句结论能不能写。

**教训（已推广到本轮所有候选）**：**任何 CV 读数都必须在最终语料上重跑**，
不能用"部分缓存先跑一遍看看"的结果进正文。部分缓存的读数只能用于判断流程是否跑通。

## CE/A39 C-hazard 的逐层 patching 在**纯 transformer 栈**上结构性退化 —— 两个架构族给出同一测量的两个退化端

**补测背景**：`candidate_expansion_DONE.md` 把 Alpamayo-R1 与 AutoVLA 的 C-hazard 列为
"未测：预算"。本轮补上，两者都跑满 12 个退化事件、36 层逐层 patching + patch-ALL 自检。

**观测**：两个 VLA 候选的恢复剖面都是**阶跃/级联**，与 TransFuser 系的**内部峰**恰好相反。

| 候选 | 可读层 | 剖面（mean recovery） | Spearman | patch-ALL | 承诺层 |
| --- | --- | --- | --- | --- | --- |
| DiffusionDrive | 8 | 0.00 … 峰 0.70 @L6 … 0.45 | **+0.929** 递增 | +1.000 | 无（任何单层都 < 0.9） |
| LTF | 8 | 0.00 … 峰 0.47 @L6 … 0.45 | **+0.929** 递增 | +1.000 | 无 |
| DiffusionDriveV2 | 8 | 0.01 … 峰 0.30 @L6 … 0.05 | +0.810 递增 | +0.552 ✗ | 无 |
| **Alpamayo-R1** | 36 | 0.58, 0.81, **≈1.0 (L2–L16)**, 0.58 … 0.49 | **−0.873** 级联 | +1.001 | **L16**（深度 0.47） |
| **AutoVLA** | 36 | **≈1.0 (L0–L20)**, 0.84, 0.77, 0.56 … 0.00 | **−0.859** 级联 | +1.000 | **L20**（深度 0.58） |

**结构性原因（不是测量失败）**：patch 第 L 层的输出后，**比 L 更深的每一层都由 clean 侧重算**。
在纯自回归 transformer 栈里残差流是**唯一**通路，故 patch 任何早期层 ⇒ 行为完全回到 clean，
recovery 在早段饱和于 1.0，剖面必然是阶跃。TransFuser 系逃过这一点，
**只是因为它的每个融合块都从 CNN 分支重新注入一份未被 patch 的图像特征**——
换言之，DD/LTF 在 L6 的内部峰是 **TransFuser 这种逐级重注入设计的属性**，
不是"危险信号在深层融合段进入网络"这件事的一般事实。

**判定**：两个 VLA 候选的 C-hazard 按 §4.4.4 的既有适用性判据（$\rho < -0.7$ 判级联）
判 **不可估（公式前提不成立）**，与 SimLingo 的 C-domain 同一处理，不是新标准。
**并且新增一条不可比声明**：$C_m$ 在 **TransFuser 系与 VLA 栈之间不可比**，
与 §4.4.2 的 F② 不可比是同一性质的结论——操作化的前提是架构相关的。

**换 patch 范围不能绕开**：另跑一次 `--tokens image`（只换图像 token 段），
AutoVLA 的剖面仍在 L0–L21 饱和于 1.0（Spearman −0.876），退化不变。
故这不是 patch 范围选得不好，是该操作化在这类栈上无分辨力。

**替代读数（本轮新增，两个 VLA 之间可比）**：**承诺层** = mean recovery ≥ 0.9 的**最深**层。
它回答"决策在多深处被定死"：AutoVLA L20 / 36（深度 0.58），Alpamayo L16 / 36（深度 0.47）。
这是阶跃剖面下唯一有信息量的形状量，已作为 `commitment_layer` 字段落盘到全部五个候选的
C-hazard json（TransFuser 系为 −1，即任何单层都不足以恢复，这本身就是"内部峰"的另一种表述）。

**Alpamayo 的采样噪声地板（本轮新增的仪器侧自检）**：Alpamayo 的 rollout 是
`top_p=0.98, temperature=0.6` 的**随机采样**（AutoVLA 是 `top_k=1` 贪心，等价确定性）。
同一输入换 5 个 seed，$v_{plan}$ 的 sd = **0.430**，达到 clean−ghost 中位 gap（1.303）的 **0.330 倍**。
本协议把两条件与全部 patch 运行**锁在同一个 seed 上**，采样噪声因此是共模的、基本抵消
（patch-ALL 实测 +1.001 而非漂移值即为证据），故该地板是**保守上界**而非实际噪声。
但它足以说明 Alpamayo 剖面上 0.88 与 1.01 之间的起伏**不可解读**，
承诺层 L16 的定位精度只能到"中段"这一粒度。已作为 `sampling_noise_floor` 字段落盘，
并加入判定门：若 sd 达到中位 gap 的 0.5 倍即直接判不可估（本次 0.330，未触发）。

**Alpamayo 的 L0/L1 不饱和（0.58 / 0.81）是一处值得记下的观察**：
patch 第 L 层输出时，**该层自己的 KV 仍是 ghost 侧的**（注意力发生在被 patch 的输出之前）。
AutoVLA 的早期层自身 KV 贡献可忽略（L0 即 1.000），Alpamayo 的不可忽略。
本轮样本量（12 事件）与上述采样噪声不足以把这条坐实，记为观察而非结论。

## CE/A40 §CE/A39 那条可证伪预测的留出检验：**证实**（含一处措辞更正）

**预测（上一轮登记在 `candidate_expansion_DONE_supplement.md` §5）**：
剖面形状由"残差流是不是唯一通路"决定 ⇒ **任何纯 transformer 栈的 C-hazard 剖面都应当是级联**。
登记时手上只有两个纯 transformer 候选（Alpamayo-R1、AutoVLA），
**SimLingo 的 C-hazard 尚未测**，构成一次真正的留出检验：
它是 InternVL2-1B（Qwen2-0.5B decoder）的纯 transformer 栈，
且此前它在**另一条配对源**（C-domain）上的剖面已知是级联，但 C-hazard 从未测过。

**检验结果：预测被证实。** SimLingo 的 C-hazard（12 事件 / 11 场景，24 层，
patch 范围沿用它自己 C-domain 的约定即 vision token 段）：

| 量 | 值 | 判据 | 结论 |
| --- | --- | --- | --- |
| patch-ALL（充分割集自检） | 均值 +0.997，中位数 **+1.009** | 须落在 [0.7, 1.3] | **通过** |
| Spearman(层号, recovery) | **−0.997** | $\rho < -0.7$ ⇒ 级联 | **级联，与预测一致** |
| 剖面 | 0.997 → 0.980 → 0.898 → … → 0.000 | —— | 单调递减 |
| $C_m$（名义值） | 0.187 [0.135, 0.279]（24 层基线 0.083） | 公式前提不成立 | **not applicable** |
| 承诺层 | **L3 / 24（深度 0.17）** | 级联下的替代读数 | 决策在很浅处即被定死 |
| **判定** | **不可估（公式前提不成立）** | | |

**六个候选按架构族完全分离，无一例外**：

| 架构族 | 候选 | 层数 | Spearman | 承诺层 |
| --- | --- | --- | --- | --- |
| TransFuser 系 | DiffusionDrive / LTF / DiffusionDriveV2 | 8 | **+0.929 / +0.929 / +0.810** | 全部**不存在** |
| 纯 transformer | **SimLingo** / Alpamayo-R1 / AutoVLA | 24 / 36 / 36 | **−0.997 / −0.873 / −0.859** | L3 / L16 / L20 |

3/3 递增 vs 3/3 级联，**符号之间没有任何重叠**。

**一处必须写出来的措辞更正**：§CE/A39 原文说纯 transformer 栈"早段必然饱和于 1.0"。
**这一半说过头了。** SimLingo 的剖面是**渐进递减**（0.997 → 0.980 → 0.898 → …），
不是 AutoVLA 那种平台式阶跃（L0–L20 恒为 1.0），因此它的承诺层只有 L3 / 24（深度 0.17）。
准确表述应为：**纯 transformer 栈的剖面必然单调递减（级联），但"平台有多宽"不是架构决定的**——
三个成员的承诺层深度分别是 0.17 / 0.47 / 0.58。
这一更正**加强而非削弱**了承诺层的价值：它是一个真正有区分度的读数，
而不是一个恒等于"很深"的常数。定性预测成立，定量外推不成立，两者都已改进正文。

**一条独立的收敛证据（预测之外的意外收获）**：
SimLingo 的 C-hazard 剖面与它自己的 **C-domain** 剖面
（配对源毫不相干：G1 clean↔ghost vs CARLA↔世界模型渲染）
Pearson $r$ = **0.968**（$p$ = 9.4e-15）、Spearman $r$ = **0.996**，两者的承诺层**同为 L3**。
同一个模型、两种毫不相干的配对来源、同一条剖面 ⇒
直接支持 §CE/A39 的核心论断：**剖面形状是模型的路由属性，不是配对来源的属性。**

**顺带更正一处数字串号**：§CE/A39 的对照表把 DiffusionDrive 的 C-hazard Spearman 写成 **+0.881**，
那实际上是它的 **C-domain** Spearman；C-hazard 是 **+0.929**（`c_axis_hazard_dd.json`）。
已在本文件与 `paper_experiments_section_{zh,en}.md` §4.4.4 更正。

## SG/A41 F① 严重度梯度：工单主读数与「单帧盲于速度」纪律的张力，未静默处理

**工单指定**：主读数用**接近速度** $v_{close}$ 作剂量坐标。

**张力**：本轮三个主对比候选（SimLingo / LTF / DiffusionDriveV2）**全是单帧模型**，
而「相对速度对单帧模型结构性不可观测」正是 D2cV 证伪地板赖以成立的**同一条前提**（§CE/A34）。
故「$b$ 不随 $v_{close}$ 分级」对单帧模型是**按构造预期**的，不能单独支持
「该候选缺乏分级机制」。早期 S1 曲线也已登记同一条纪律
（"SimLingo 严格单帧、实测盲于速度 ⇒ TTC 不可当剂量轴，改用 $d_{long}$"）。

**处理**：**不改工单主读数**（改了本报告就与工单不可对齐），
而是把 $d_{long}$（单帧可观测剂量）对照**升为必需项**并在正文并读。
两条并读才能区分「看不见剂量」与「看得见但不分级」。

**这条张力的解决方式本身是一个结果**：同一条纪律在任务一（剂量坐标）与任务二（证伪地板）
上给出**同一个约束**，这正是纪律而非临时决定的标志。

**顺带新增的必需控制**：$v_{close}$ 与多个**单帧可见**量相关
（$d_{long}$ +0.25、$\log$ 成像面积 −0.18、$|lat|$ −0.25、离心率 −0.15、ego 速度 +0.25）。
故加两个多元规格。实测：SimLingo 的 $v_{close}$ 在基本规格下存活（−0.084，CI 不含 0），
**加入可见几何后 CI 含 0**；四个候选无一在全控后存活。
**单变量上那条「越紧迫越不刹」因此不能按字面写进结论**——
它可由单帧可见的成像几何解释，不需要假设模型感知了速度。
单变量数字原样留在报告 Table 1 供核查，不删。

## LB/A42 第二场景负例匹配的两处修正（都在跑推理之前抓出来）

**修正一：漏匹配自车车速。** 首版按 N1 的口径只匹配「距离 + 前车车速」，
实测 LB vs LBn 的自车车速 **SMD = +0.600** —— 前车急刹与自车开得快本就相关，
而自车车速**强驱动**各模型的下发速度。不匹配的话，G/F 上测到的差异会混入
「这一组自车本来就开得快」。加入第三个匹配变量后降到 **+0.239**。
**这是本场景相对 G1 新增的混杂**：G1 的 A/D2a 是"有没有一个 VRU 出现"，
自车状态与之无强相关；本场景的正例定义**本身就与自车状态相关**。
**换场景时不能照抄上一场景的匹配变量清单，要重新问一遍"什么和正例定义相关"。**

**修正二：贪心最近邻改为最优指派（匈牙利算法）。**
贪心结果依赖遍历顺序（要靠随机种子），且在负例池小时容易先用掉好负例，
使后续正例只能配到边缘样本。最优指派最小化总配对距离、无顺序依赖、可复现。
LBn 因此 46 → 48 且 SMD 改善。**LBv 一格未动**——它的池子已被 caliper 榨干
（37 个候选中 31 个入选），这恰好证明 LBv 的限制在**语料**而不在算法，
并把这条写进了挖掘报告与泛化报告的局限。

## LB/A43 刹车灯无标注：LBv 的替代构造与其未经核实的假设

工单要求"按刹车灯标注是否可得来具体设计"。**nuScenes 没有刹车灯标注。**

**替代构造**：让 LBv 的负例**本身也在减速**（幅度小，$-1.5 \le a \le -0.3$ m/s²），
因此两臂的刹车灯**很可能都亮**，差异被压到减速度幅度这一个维度——
与 D2cV「控制住可见线索，让唯一差异落在单帧结构性看不见的量上」同构。

**代价必须写明**：我们**无法核实刹车灯确实亮**。这条记为限制，不作为已验证的控制。
若模型确实只在"认刹车灯"，本设计**倾向于**暴露它（LB 与 LBv 的刹车灯状态相近），
但该推论依赖上述未经核实的假设。**不得把「LBv 反超」直接读成「模型只看刹车灯」。**

## LB/A44 阈值回调需要一条分位数给不出的**物理**上界

G1 当年的 A/B/C 阈值全部按分布分位数回调。本场景照做会出问题：
$a_{\min}$ 的 p10 = −10.20、p5 = −13.67、p1 = −27.98，
而**路面车辆的物理制动极限约 −8 ~ −9 m/s²**（干燥沥青紧急制动）。
按分位数取尾部会把 32 个 nuScenes 2 Hz 标注差分伪影当成"最严重的正例"，
且它们的 clean/ghost 对比会被当作最强信号。

**处理**：正例带取 $-10 \le a \le -3$，$a < -10$ 的 32 个**判为伪影剔除并记录数量**。
**这是 G1 阈值回调纪律在新场景上的一处必要扩展**：
分位数回答"多少算罕见"，物理上界回答"多少算可能"，两者都要。

# 第三轮（navsim_openscene_independent_corpus 工单）

## NS/A45 NAVSIM 无 attribute 标注：`is_parked` 改按运动学定义

G1 侧的 `is_parked` 取自 nuScenes 的 `vehicle.parked` / `vehicle.stopped` **属性标注**
（占该轨迹属性帧的 80% 以上即判停驻）。**NAVSIM/OpenScene 的 anns 里没有 attribute 字段。**

**替代定义**：车辆类目标，且全轨迹绝对速率的最大值 < 0.5 m/s。
这是**定义偏离**而非等价替换：nuScenes 的 `parked` 是标注员判断的**意图/状态**，
本定义是**运动学阈值**，两者在"临时停车等红灯"这类情形上会分歧
（nuScenes 标 `stopped`，本定义也判停驻；但"低速蠕行"nuScenes 可能标 `moving`，本定义判非停驻）。

**影响面**：`is_parked` 只用于 D2a_parked（D2aP）这一支负例的构造，
不进入本轮的主读数（A vs D2a、D2cV 地板）。故记为偏离并声明影响面，不做额外校正。

## NS/A46 裁剪主点行必须随语料走 —— 一处**会静默污染读数**的硬编码

`run_ghosthead_infer.CROP_CENTER_ROW = 450` 是 4:1 去天空裁剪的竖直中心，
注释写明它是"主点行"。450 正是 **nuScenes CAM_FRONT（1600×900，主点 (800, 450)）** 的主点行。

**NAVSIM CAM_F0 是 1920×1080、主点 (960, 560)。** 沿用 450 会把裁剪带整体上移 110 px
（裁 rows 210–690 而非 320–800），等于给三个模型喂一条**偏高、多天空少路面**的画面，
且 `bbox_to_tokens` 的 region 池化会跟着错位。这不会报错，只会静默地降低全部读数。

**处理**：新增 `dd_adapter.set_crop_center_row()`，由各缓存/patching 脚本按语料传入
（nuScenes 450，NAVSIM 560）。**默认值不变 ⇒ 既有 nuScenes 侧全部读数逐位不变。**

**教训（比这条修正本身重要）**：跨数据源迁移时，**"看起来是通用前处理的常量"往往编码了原数据源的相机几何**。
本轮从 nuScenes 换到 NAVSIM 只改了数据读取层，但这个常量藏在**模型前端**而不是数据层里，
不逐个核对相机内参就会漏掉。已在挖掘报告里把"相机几何逐项核对"列为跨数据源的必查项。

## NS/A47 DiffusionDriveV2 的点云读取器：NAVSIM 侧反而更简单（成本反转的一个具体例子）

DDv2 必须喂真实 lidar（§CE/A29、§CE/A33）。两个数据源的读取成本恰好相反：

| | nuScenes | NAVSIM/OpenScene |
| --- | --- | --- |
| 定位点云 | 由 CAM_FRONT 的 sample_data → sample → LIDAR_TOP 三跳 | 帧里直接给 `lidar_path` |
| 坐标系 | LIDAR_TOP 系，需查 `calibrated_sensor` 做 sensor→ego 变换 | `lidar2ego` 是恒等（已实测核对）⇒ **天然在 ego 系** |
| 文件格式 | `.pcd.bin`（裸 float32×5） | `.pcd`（二进制，带 header，需解析 FIELDS/SIZE） |
| 依赖 | nuScenes devkit | 无（20 行解析） |

净效果：`NavsimLidar` 比 `NuScenesLidar` 更短、依赖更少。这是工单预期的"成本反转"的一个实例，
但**反转的来源不是模型侧而是数据侧**——详见挖掘报告 §成本反转。

## NS/A48 **LTF 的 G 轴阳性在独立数据源上未能复现，且这次不是功效问题**

**这是本轮的核心结论，必须与"前车急刹"那次的"不可估"严格区分开。**

| | G1（nuScenes） | 第二场景（前车急刹） | **本轮（NAVSIM 独立语料）** |
| --- | --- | --- | --- |
| 主读数 − 证伪地板 | **+0.070 [+0.017, +0.126]** | +0.032 [−0.098, +0.164] | **+0.011 [−0.038, +0.065]** |
| CI 宽度 | 0.109 | 0.262（**2.4×**） | **0.103（0.94×，略窄）** |
| 10 seed 折分配 | +0.056 ± 0.028 | +0.000 ± 0.067 | +0.022 ± 0.022 |
| 正例 / 地板 n | 291 / 212 | 103 / 31 | **397 / 134** |

**前车急刹那次判"不可估"的理由是 CI 宽了 2.4 倍**——功效不足足以解释点估计的缩水。
**本轮不成立**：CI 宽度 0.103 **比 G1 的 0.109 还略窄**，即功效相当甚至更好，
而效应量从 +0.070 掉到 +0.011。**因此这是一次有信息量的不复现，不是一个功效不足的空结果。**

**同时注意主读数本身是复现的、而且更强**：A vs D2a 的 CV-AUC 在 NAVSIM 上是
**0.630 [0.592, 0.669]，p = 3.1 × 10⁻¹⁰**（G1 是 0.623）。
掉下去的是**主读数与证伪地板之差**：D2cV 地板从 G1 的 0.553 升到 **0.620**。
**即：LTF 在新语料上把"A vs 几何匹配静物"分得同样好甚至更好，
但它把"A vs 同类别同几何、只差相对速度的 VRU"也分得同样好。**
按 D2cV 的构造，后者是单帧模型**结构性不可能**做到的判别，
故这条方向读到的更可能是"画面里有个 VRU"而不是"这个 VRU 危险"。

**这正是证伪地板存在的全部理由**：若只看主读数，会得到
"LTF 在独立数据源上把 G 轴阳性复现得更强了"这个结论，而它是错的。

**不宣称的部分**：本轮**不能**据此断言 G1 上的 +0.070 是噪声。
两个语料在相机几何、标注管线、城市构成上都不同，
"效应真实但对语料敏感"与"效应本就是噪声"在本设计下不可区分。
准确表述是：**该阳性不具备跨数据源的稳健性，因而不能作为"LTF 具备危险概念"的证据。**

# 第四轮（g_vs_f3_simplified_axes 工单）

## GF/A49 G-VS 探针首版**未收敛**，selectivity ≈ 0 是优化失败而不是"表征没信息"

**首版实现**：手写全批梯度下降（200 步，lr 0.5，L2 正则）的逻辑回归探针。
**实测**：LTF 上 trained mIoU = **0.2971**、random_init = 0.3002、selectivity = −0.003。

**为什么这是优化失败而不是结果**：本任务二类、object token 占比 0.413。
"全预测背景"的解析 mIoU = IoU(bg)/2 = 0.587/2 ≈ **0.294**；
"全预测物体" = 0.413/2 ≈ 0.207。实测 0.2971 **恰好落在"全预测背景"这个退化解上**，
三个臂（trained / random / position）也几乎同值——典型的欠拟合签名。

**处理**：换成 `sklearn.linear_model.LogisticRegression(solver="lbfgs", max_iter=1000,
class_weight="balanced")`。**探针仍是单层线性、不加隐层**——
Hewitt & Liang 2019 的核心论点是探针容量越大 selectivity 越不可信，
所以这里换的是**优化器**不是**模型容量**。改后 LTF 三臂分离
（0.3672 / 0.3481 / 0.3331），selectivity 变为可读的量。

**教训**：探针类实验里，"三个对照臂读数几乎相同"要先怀疑优化，再怀疑表征。
本轮若不核对退化解的解析值，会得到"六个候选的表征里都没有物体性信息"这个错误结论。

## GF/A50 G-VS 只覆盖 6 个候选中的 4 个：两个 VLA 的 video token 布局

**已覆盖**：DiffusionDrive / LTF / DiffusionDriveV2（8×32 token 网格覆盖 4:1 裁剪带，映射精确）、
SimLingo（InternVL2 的 tile 网格，每 tile 16×16 token，复用 `image_to_token_grid` 的同一套几何）。

**未覆盖**：Alpamayo-R1、AutoVLA。

**AutoVLA 的布局其实已经解出来了**（本轮的实质进展，留给后续直接用）：
`get_prompt` 返回 `video_grid_thw = [[2,18,32]] × 3`（3 路相机各一个 video），
Qwen2.5-VL patch 14 px + 2×2 merge ⇒ 每路 2 时间组 × 9 × 16 = 288 token，
三路合计 864，与实测图像 token 数一致；前视相机最后一个时间组的 9×16 = 144 个 token
均匀覆盖前视全幅（1600×900 → 448×252，宽高比一致、无裁剪）。
**卡住的是实现而不是原理**：加了随机初始化对照臂之后（同 GPU 上两份 3B 模型），
前向在模型内部抛 IndexError（空的图像 token 索引），本轮时间盒内未定位。

**Alpamayo 未解**：6 路相机 × 多时刻的 video token 分组未核对。

**如实记录而不是硬凑**：不用"取平均 token"或"随便挑一段 token"来凑满六个候选——
那样得到的 mIoU 不可解释，比缺格更糟。G-VS 的统一矩阵因此标注为 **4/6 覆盖**，
两个 VLA 记 n.m.（未测，非不适用），并把已解出的 AutoVLA 布局写进本条供后续直接接。

## GF/A51 F-3 的 ctrl 对照臂是必需项，不是稳健性附录

F-3 的 occ 臂同时做了两件事：**移除了这个实体** + **在画面里加了一块灰斑**。
只有 occ 臂时，一个"对任意灰斑都会反应"的模型会被误判为通过必要性检验。

故本轮把 **ctrl 臂**（同面积、同离心率带、不与原框重叠的对照框）设为**必跑**。
实测它确实起了作用：六个候选的 $R_{ctrl}$ 全部落在 [−0.09, +0.16] 且 CI 跨 0，
即"在别处涂一块灰斑"不会让动作退回基线。
**这使 LTF 的 FAIL 判定（$R$ = +0.113 [0.044, 0.191]）站得住**：
不是"遮挡这个操作本身无效"，而是"遮住**这个实体**无效"。

这条与 N1 的 D2a 几何匹配、C-hazard 的 patch-ALL 自检同源：
**任何干预都要配一个只差目标语义的对照**。

## GF/A52 F-3 的主要结论是"六个候选里只有两个存在可供检验的响应"

四个候选（DiffusionDrive、DiffusionDriveV2、Alpamayo-R1、AutoVLA）的
$b_{ghost} = v_{plan}(\text{ghost}) - v_{plan}(\text{clean})$ 本身与 0 不可区分，
因此**没有可供必要性检验的响应**——这不是必要性检验失败，是无从检验。
判定写成"不可估：基线响应本身不存在"，**不写成 FAIL**。

两者的区别在诊断上是实质性的：
* **FAIL**（LTF）：有响应，但响应不是被该实体的可见性驱动的 ⇒ 盲目泛化签名，需要查驱动源；
* **不可估（无基线响应）**（其余四个）：压根没有对危险帧的动作响应 ⇒ 要先让它有响应。
把两者都写成"没通过"会把两种完全不同的修复处方压成一个。

## GF/A53 G-VS 的 `position_only` 地板在 NAVSIM 上**超过** trained —— 两条对照臂里这一条更有信息量

**观测**：NAVSIM 语料上，只用 token 的 (row, col) 坐标训探针，mIoU 达到 **0.371**
（G1/前车急刹上只有 0.331~0.337）；两格甚至超过了 trained mIoU
（DiffusionDriveV2 0.371 vs 0.355；SimLingo 0.411 vs 0.408）。

**原因**：NAVSIM 相机 1920×1080、主点 (960, 560)，4:1 裁剪带的构图与 nuScenes 不同，
物体在画幅内位置分布更规律 ⇒ 仅凭坐标就能猜得更准。**这是语料属性，不是模型属性。**

**对判定的影响（要分清楚，不能一句话带过）**：
* **selectivity 仍然有效**：它是对 `random_init` 的**配对差**，两臂共享同一套 token 坐标，
  坐标先验在差里被抵消。四格 PASS 不受影响，无需回退。
* **但"G-VS PASS"的语义必须收窄**：它支持"表征含有超出随机初始化的物体性信息"，
  **不支持**"表征提供了实用的物体定位能力"——在 NAVSIM 上，一个平凡坐标基线
  在绝对 mIoU 上就赢过了两个候选的表征探针。

**这条为什么重要**：G-VS 是本文自己提出的"更客观"的新轴。
若当初只报 selectivity、不设 `position_only` 臂，本轮换语料就不会暴露它。
**两条必需对照臂里，这次是 position_only 而不是 random_init 抓到了问题。**
这也是"不因为是自家新轴就放松判定标准"这条要求的一个具体兑现。

## GF/A54 F-3 的可测性依赖"该语料上存在基线响应"，这是它的结构性限制

F-3 的必要性比 $R = 1 - b_{occ}/b_{ghost}$ 以 $b_{ghost} \ne 0$ 为前提。
三语料实测：

| 候选 | G1 | 前车急刹 | NAVSIM |
| --- | --- | --- | --- |
| LTF | $b_{ghost}$ 显著 ⇒ **可测（FAIL）** | 不显著 ⇒ 无从检验 | 显著 ⇒ **可测（FAIL）** |
| SimLingo | 显著 ⇒ 可测 | 不显著 ⇒ 无从检验 | 显著 ⇒ 可测 |
| DiffusionDrive / DDv2 | 不显著 | 不显著 | 不显著 |
| Alpamayo-R1 / AutoVLA | 不显著 | 不显著 | NAVSIM n/a（接口缺失） |

**16 个可算格里只有 4 格可测。** 前车急刹语料上**六个候选全部失去基线响应**，
故该语料对 F-3 完全不提供信息——这与它在 F①、G 轴上同样全线不可估是一致的
（见 `second_scenario_generality_report_*`），即**该语料的行为端信号本身很弱**，
不是 F-3 这个操作化的问题。

**判定纪律照旧**：这些格一律记"不可估：基线响应本身不存在"，**不记 FAIL**。
两者修复处方不同（§GF/A52），跨语料复现表里也必须保持这个区分。

## GF/A55 LTF 的 F-3 FAIL 跨数据源复现 —— 本工作线里少见的"点估计与判定同时复现"

| 量 | G1 | NAVSIM |
| --- | --- | --- |
| $b_{ghost}$ | −0.0245 [−0.0384, −0.0102] | **−0.0249 [−0.0399, −0.0099]** |
| 必要性比 $R$ | +0.113 [+0.044, +0.191] | **+0.008 [−0.068, +0.078]** |
| $R_{ctrl}$ | +0.029 [−0.031, +0.081] | −0.033 [−0.132, +0.054] |
| 判定 | **FAIL** | **FAIL** |

## FM/A56 F-3 对多帧候选只遮窗口最后一帧 —— 正确性缺陷，已修复

## FM/A57 「早于 emergence」≠「看不见」—— 工单对 AutoVLA 的估计需要更正

工单按 `t_emergence` 推断 AutoVLA 的前几帧大概率在 emergence 之前、因而看不到实体
（按该判据算，288 个事件里 0% 受影响）。**逐帧投影实测否定了这一点**：
AutoVLA 窗口 4 帧里平均 **3.44 帧**能投影出实体，119 个事件里 85 个是 4 帧全可见。

**原因**：`t_emergence` 是"进入走廊 / TTC 越阈"的时刻，**不是"变得可见"的时刻**。
行人在进入走廊之前往往已经在人行道上清晰可见。

**推广到纪律**：凡是"某帧看不看得见某实体"这种判断，
**必须逐帧投影核实，不能用事件级的时间判据代推**。
本条同时说明：一个看起来只影响一个候选的缺陷，不核实就可能实际影响两个。

## FM/A58 修复后判定未变，以及由此顺带得到的两条东西

**判定未变**：两个候选修复前后都是「不可估：基线响应本身与 0 不可区分」。

**为什么不可能变（必须写清楚，否则会被读成"漏洞无害"）**：
三态判定的门是 $b_{ghost}$（**未遮挡臂**，clean vs ghost），修复完全不触及它。
两个候选的 $b_{ghost}$ CI 都跨 0 ⇒ 卡在这一步，$R$ 根本不参与判定。
**正确读法是"这两格恰好在更前面的一道门被拦住，漏洞影响的那一段没被用到"**，
而不是"漏洞无害"。若它们像 LTF 那样有基线响应，$R$ 就会被系统性测错。

**顺带得到的一条噪声地板**：$b_{ghost}$ 按构造不该受修复影响，
故它的实测非零量就是运行间噪声地板：

| 候选 | $\Delta b_{ghost}$（噪声地板） | $\Delta b_{occ}$（修复效应） | 比值 |
| --- | --- | --- | --- |
| Alpamayo-R1 | 0/99 非零，均值 0.0000 | 99/99 非零，均值 0.1144 | ∞ |
| AutoVLA | 3/119 非零，均值 0.0012（最大 0.103） | 24/119 非零，均值 0.0196 | **16.3×** |

Alpamayo 因锁 seed 噪声严格为 0；**AutoVLA 的 `temperature=1e-4 + top_k=1` 接近但不是
比特级确定性**，此前未被量化，本轮顺带得到，可作为"多次推理取平均降噪"那个工单的输入。

**顺带发现的另一条同性质缺陷（未修，已登记）**：
**DiffusionDriveV2 的 F-3 遮挡只涂 RGB 图像，而它同时吃 ghost 帧的真实 lidar 点云**
（§CE/A29、§CE/A33 要求必须喂真实 lidar）⇒ **行人在点云里仍然完整存在**。
对 DDv2 而言"遮挡"从未把实体从输入里移除，只是从相机里移除。
当前 DDv2 的 F-3 判定同样是"无基线响应"、卡在 $b_{ghost}$，故现有结论不受影响；
但这是与本工单同性质的正确性缺陷，正确做法是同时删掉落在该 3D 框内的点云点。
本工单范围只涵盖多帧遮挡，未做，列入未完成项。

**单帧候选的其余通道已核查无泄漏**：`spd(ev)` 是标量、取自 **clean** 侧、三臂共用同一值，
不携带实体信息；单帧模型只吃一张图，遮挡即完全移除，不存在"历史帧"通道。

## FM/A59 DDv2 的 lidar 通道已堵上；**并更正 §FM/A58 的一句过头话**

**修复**：F-3 对 DiffusionDriveV2 现在在涂 RGB 的同时，

**按构造不可能改变判定**。

**更正 §FM/A58 的一句话**：上一轮我写的是
"**行人在点云里仍然完整存在**"。**这句说过头了，与实测不符。**
G1 的 A 类正例 VRU 中位纵距 **27.1 m**，而 nuScenes 是 32 线激光雷达 ⇒

m=0.0 时中位为 0、均值 2.1。

但在 G1 这份语料上，实体本来就几乎不在点云里，故该泄漏的实际暴露面很小。"

**修复效应与噪声地板**：DDv2 是三个 F-3 候选里**唯一比特级确定性**的
（$\Delta b_{ghost}$ 严格 0/282 非零，无采样解码）。
$\Delta b_{occ}$ 均值 **+0.0051 [−0.0036, +0.0145]**，**CI 跨 0** ⇒
堵上 lidar 带来的行为变化与 0 不可区分；178/282 个事件的 $b_{occ}$ **一位没变**

**为什么仍然必须修**：① 正确性问题不该依赖"这个语料恰好点少"这个偶然事实；
② 换到近距事件或更高线数传感器（NAVSIM/OpenScene 的 MergedPointCloud）暴露面会立刻变大；

**不为凑数去挑删点数匹配的对照位置**——那会让对照框位置由点云密度决定，引入新的选择偏差。

# 第六轮：F-3 距离读数（FD）

> 工单：2026-09-03。承接 §FC/A60–A62（累计 62 条）。

## FD/A63 工单指定的主读数被判为不可用（诊断而非改口径）

**工单指定**：$b^{(d)}_{ghost} = d_{plan}(\text{ghost}) - d_{plan}(\text{clean})$，
$d_{plan}$ = 轨迹终点到危险实体的欧氏距离，预期为**正**。

**实测**：六个候选的 $b^{(d)}_{ghost}$ 全部显著非 0，但**纯几何项占 81%–108%**——
危险实体在两帧之间自身走近约 6 m（纵距中位 30.5 → 24.6 m），
规划**完全不变**时也会产生同量级的 $b^{(d)}$。此外两帧之间 **ego 自身还移动了中位 7.2–8.2 m**，
这一项在任何跨帧比较里都无法消除；混淆调整后的效应只有该残留的 **0.008–0.130 倍**。

**处理（三条，都不改口径）**：
1. **照跑照报**工单指定的主读数，同时**显式算出**纯几何项
   （$d^{null}$ = clean 臂轨迹 vs ghost 帧实体位置）与调整项，用诊断量说明它为什么不可用；
2. **机械套用速度版三态判据会给出六个 FAIL，明确不采纳**——那道门被几何单独打开，
   与模型有没有反应无关。机械结果保留在 `verdict_mechanical` 字段供复核，
   `verdict` 改为"不可估：主读数的门被几何混淆打开"；
3. **不换一个更有利的 action 定义**（例如"轨迹到实体的最小距离"）去让结果好看——那属于事后挑口径。

**一条方法学结论（本轮最有价值的产出）**：
**跨帧的 action 读数，只要 action 量不是"起点不变量"，就会被几何主导。**
速度是起点不变量，距离不是。⇒ 把 action 换成空间量时，**必须同时把对比换成同帧对比**。
这也为"用 $d_{occ}$ 重构 F-3 的门"这个待办增加了一条独立支持：
两个不同的 action 读数下，**跨帧的分母都是被污染的那项、同帧的分子都是干净的那项**，
说明问题出在**跨帧对比这个设计**上，不是某个 action 量的选择。

## FD/A64 距离读数的三处口径决定

**① 分母守卫门槛 0.02 → 0.5**：速度版门槛量纲是 m/s，距离版是 m，不可移植。
该改动不影响本轮结论（门本身已被判无效），但仍登记，避免留下"沿用旧门槛"的错觉。

**② SimLingo 的特异性检验差一点点，未放宽**：$\delta_{occ}$ = −0.306 [−0.630, −0.024] 显著，
但配对量 $|\delta_{occ}|-|\delta_{ctrl}|$ = +0.296 **[−0.005, +0.630]，CI 下界擦着 0**

## FE/A65 弧长读数的口径决定

**① 两种 $L$ 定义都算，不只选一种**（工单要求）：
$L^{arc} = \|w_0\| + \sum_i\|w_{i+1}-w_i\|$（含 ego 原点到首点那一段）、
$L^{end} = \|w_{-1}\|$。另算 $L^{arc\text{-}nw}$（不含原点段）作稳健性对照。
**实测三种定义在 6 个候选上给出相同的显著性、特异性与判定**（12 格全同），
点估计最大差 0.14（出现在时域最长的 Alpamayo）。

**② 分母守卫沿用 0.5 m**（与距离版同量纲），不新设。

**③ 起点不变性做实测核验而非只声明构造性**：把逐事件 $b^{(L)}_{ghost}$ 与上一轮存下的
两帧间 ego 位移做 Spearman 相关：弧长版 |ρ| ≤ 0.24（三个在 0.13 以内），
距离版在四个候选上是 −0.47 ~ −0.61。⇒ **上一轮的诊断（距离读数被几何污染，因为它不是
起点不变量）被证实；混淆确实消掉了。但判定依然不变** ⇒ 上一轮的零结果不是那个混淆造成的。

## FE/A66 (a) 配对 vs (b) 分组均值：点估计必然相同，功效全在配对上

工单要求两种算法都做并说明是否一致。**数学上**同一批事件、两臂无缺失时
$\overline{L(occ)-L(ghost)} = \overline{L(occ)}-\overline{L(ghost)}$（均值线性性）
⇒ 点估计必然逐位相同。**实测吻合**：六候选 × 两定义共 12 格，差值全在 $10^{-15}$ 量级（浮点舍入）。

差别只在 CI，且取决于 bootstrap 怎么做：
* **(b1) 两组用同一次 scene 重抽** ⇒ 与 (a) 完全等价，CI 半宽逐位相同（配对结构被保留）；
* **(b2) 两组各自独立重抽** ⇒ CI 撑宽 **4.8–13.6 倍**，SimLingo 的 $\delta_{occ}$ 会从显著变不显著。

原因：事件间差异（规划长度 10–13 m 的跨度）比臂间差异（0.29 m）大**两个数量级**，只有配对能约掉。
⇒ **配对设计的全部功效来自"同一批事件、同一次重抽"，不是来自读数本身。**
本项目所有四臂读数必须走配对/共享重抽，这条本轮得到定量确认。

## FE/A67 R 的估计量影响一格已发表判定（发现，未单方面改动）

**发现**：把 R 从"逐事件比值的均值"换成"汇总均值之比"
$R = \overline{b_{ghost}-b_{occ}}/\overline{b_{ghost}}$（同一套 scene 级 bootstrap）后，
**论文 Table 3 里 LTF 在发现语料（G1）上的 FAIL 变成不可估**：
+0.113 [+0.044, +0.191]（FAIL）→ **+0.283 [+0.158, +0.680]（CI 上界 > 0.5 ⇒ 不可估）**。

**影响面（逐格界定）**：
| 格 | 是否受影响 | 说明 |
| --- | --- | --- |
| **G1 × LTF** | **受影响** | 门开着 ⇒ R 进判定；FAIL → 不可估 |
| NAVSIM × LTF | 不受影响 | 两估计量都 FAIL（+0.008 / +0.010）⇒ **论文的"LTF 签名在 NAVSIM 复现"仍成立** |
| G1 / NAVSIM × SimLingo | 不受影响 | 两估计量都判不可估 |
| G1 × DD、G1 × DDv2 | **无后果** | 门（b_ghost 显著）本来关着，R 不参与判定 |

**处理（三条）**：
1. **不单方面换估计量**。"哪个才是 F-3 想要的"是需要专门决定的方法学问题：
   逐事件比值均值估"各事件必要性比的平均"，汇总均值之比估"平均响应里被移除的比例"，
   而 PASS 门槛（"遮挡要移除过半的响应"）字面上更贴近后者。该选择影响这条线**全部** R 读数，
   **不应在一轮关于弧长的分析里顺手定掉**。登记为**最高优先级待决项**。
2. **不单方面改论文**。把发现与影响面写清（报告 §4），待估计量定案后一并处理。
3. **本轮自己的判定里，遇到两估计量不一致就判不可估**。SimLingo 即如此：
   $R^{(L)}$ 逐事件比值均值 −0.063 [−0.248, +0.088]（FAIL）vs 汇总均值之比
   +0.407 [+0.107, +1.327]（不可估）⇒ 判不可估。
   **若不做这一步核查，本轮会宣布"弧长读数把 SimLingo 测成 FAIL"这样一个站不住的新发现。**

## FE/A68 本轮读数自身的局限（自行指出）

$L^{arc}$ 与 $L^{end}$ 都是**纵向伸展量**，与速度版同帧擦除效应的逐事件相关达
|ρ| = 0.38–0.73（DDv2 −0.619、SimLingo −0.725）。
$L \approx$ 「整个时域上的平均速度 × 时域长度」，而 $v_{plan}$ 是「第一步的瞬时速度」
⇒ **两者是同一物理量在不同时窗上的读数，不是两种独立信息。**

⇒ 工单的动机（"反应体现在改路径而不是改速度"）**只被部分覆盖**：
覆盖了"改路径**长度**"，没覆盖"改路径**形状/横向偏移**"。
真正正交于速度的量必须是**横向的**（轨迹横向偏移量、或轨迹到实体的最小横向间距）。
**本轮不顺手改口径去试它**（同一轮内换 action 定义属事后挑口径），登记为待预注册项。

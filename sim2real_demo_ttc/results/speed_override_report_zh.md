# 速度覆盖实验报告：把"当前速度观测"统一控制成受控值

> 工单：2026-09-03（插队）。**这不是给模型下达目标速度**——接口调查
> （`target_speed_interface_report_zh.md`）已确认除 SimLingo 外都没有目标速度通道。
> 本轮做的是**控制一个协变量**：把喂给模型的"当前速度观测"统一覆盖为
> $\max(\text{真实速度},\ F)$，与遮挡一样是主动构造的反事实输入。
> 旧结果一律未改未删，新结果用 `_spdctrl` 后缀另存。

## 0. 结论先行

**这个操控在 F-3 上不成立，方向与预期相反。**

1. **AutoVLA 没通过合理性检查**（输出量化坍缩），按工单条件**未重跑**。
2. **判定确实变了，但是变坏**：LTF 与 SimLingo 的门**从开变关**——
   $b_{ghost}$ 缩小到跨 0，从"有基线响应可供检验"退回"无从检验"。
3. **机制已定位**：覆盖放大的是**幅度**不是**信号**。三个候选的方向一致率
   全部塌向 50%（掷硬币），逐事件 $\lvert b_{ghost}\rvert$ 涨 1.3–1.6 倍，
   **信噪比降到原来的 0.24–0.32 倍**。
4. **前提本身有误**：$b_{ghost}$ 是**同事件配对差**，两臂本就共用同一个喂入速度
   ⇒ 跨事件的背景速度差异**在配对时已经抵消**，从来没进入过 $b_{ghost}$。
   覆盖消不掉本来就不存在的噪声，反而制造了跨模态矛盾的输入。

**样本量利好（工单第 3 项）确实存在但兑现不了**：新池里 $v_0<3$ m/s 的有
7 事件 / 7 scene（占 18 个的 39%），旧池 T2 有 4 事件 / 2 scene；
若覆盖可用即可回收，但鉴于第 3 点，不建议。

## 1. 实现

`scripts/f3_occlusion_necessity.py:129`（新增 `--speed-floor`，默认 0 = 关闭）
与 `scripts/f3_occlusion_vla.py:62`（同名参数，`alpa` 传入直接报错退出）。

```python
def spd(ev):
    v = float(np.mean([f["ego_speed_mps"] for f in ev["x_clean_frames"]]))
    return max(v, args.speed_floor) if args.speed_floor > 0 else v
```

**除这一项外全部未改**：图像、遮挡框、对照框、事件集、随机种子、四臂结构一律照旧。
四臂共用同一个 `spd(ev)`（锚在 clean），与原口径一致。

### 2.1 AutoVLA：**未通过**

唯一值随覆盖值单调坍缩：**24 → 20 → 10 → 5**（24 个**不同**图像）。

| 覆盖值 | 最常见取值 |
| --- | --- |
| 真实 | 3.503×1, 6.059×1, 7.73×1（全部互不相同） |
| 8 | 7.627×5, 7.73×5, 7.895×4 ⇒ **14/24 塌到 3 个值** |

原因可追溯：AutoVLA 的轨迹输出是 token 化的，其系统 prompt 里有明确的纵向动作词表
（`models/autovla.py:654`：`[stop, deceleration to zero, maintain constant speed,
quick deceleration, deceleration, quick acceleration, acceleration]`）。
被推出自然速度范围后，输出坍缩到少数几个动作 token，**图像基本不再起作用**。

> **按工单"确认合理之后才重跑"的条件，AutoVLA 不满足前提，本轮未重跑 F-3。**
> 在 floor8 上跑出来的 $b_{ghost}$ 会因两臂同时坍缩到同一个 token 而趋近 0，
> 那反映的是量化不是模型。**这条路对 AutoVLA 不通**，不设计变通方案。
> （floor=5 时 20/24 唯一，尚属边缘可用，但那不是主口径。）

### 2.2 覆盖值敏感性：8 是三个里唯一稳的

* **floor=11**：DD 与 DDv2 的图像驱动变异分别暴涨到 0.7153 与 3.2725
  （相对 floor8 的 4.6× 与 1.8×），且 DD 的输出不再跟随输入
  （喂 11.00 → 输出均值 9.775）。这是被推出分布的迹象，不是"信号变强"。
* **floor=5**：对多数事件抬升幅度小（真实速度中位 5.57），操控力度不足。
* **floor=8** 三个 TransFuser 系候选与 SimLingo 均不退化 ⇒ 作为主口径。

**这也说明结论不是只测一个数字得出的**：三个覆盖值给出一致的图景。

## 4. 机制：覆盖放大的是幅度不是信号

**Table 3. 逐事件诊断（n=282）。**

| 候选 | 方向一致率（负=看到危险后减速） | 逐事件 $\lvert b_{ghost}\rvert$ | 带符号均值 | **信噪比 $\lvert\mu\rvert/\sigma$** |
| --- | --- | --- | --- | --- |
| LTF | 61.7% → **51.1%** | 0.0706 → 0.0891（**1.26×**） | −0.0245 → −0.0098 | 0.2542 → 0.0815（**0.32×**） |
| DiffusionDrive | 56.7% → **52.1%** | 0.1658 → 0.2575（**1.55×**） | −0.0289 → +0.0086 | 0.0694 → 0.0170（**0.24×**） |
| DiffusionDriveV2 | 55.3% → **46.5%** | 1.0075 → 1.3328（**1.32×**） | −0.1803 → +0.0683 | 0.1310 → 0.0358（**0.27×**） |
| SimLingo | 56.4% → **54.6%** | 1.2859 → 0.9622（**0.75×**） | −0.4441 → −0.1807 | 0.2278 → 0.1313（**0.58×**） |

**四个候选在结果上一致、在机制上分两类**：

* **共同点（结论所系）**：方向一致率全部下滑、**信噪比全部退化**（0.24× / 0.27× / 0.32× / 0.58×），
  带符号均值全部向 0 收缩。两个原本门开的候选（LTF、SimLingo）**门都关上了**。
* **分歧点（如实记）**：TransFuser 三兄弟的逐事件 $\lvert b_{ghost}\rvert$ **涨** 1.26–1.55 倍
  （噪声被放大），而 SimLingo 是 **降** 到 0.75 倍（响应被压扁）。
  两条路径不同，但都导致信噪比下降 —— 前者分母涨得比分子快，后者分子降得比分母快。
  **不能笼统说"四个候选机制相同"**，只能说结论方向相同。

**这就是"把信号变成噪声"的定量定义 —— 四个候选无一例外。**

### 4.1 退化随速度抬升量单调加重

**Table 4. 按覆盖抬高了多少速度分桶，逐事件 $\lvert b_{ghost}\rvert$ 的变化比值。**

| 抬升量 | n | LTF | DiffusionDrive |
| --- | --- | --- | --- |
| **未抬高**（真实 ≥8） | 46 | **1.00**（逐位相同） | **1.00**（逐位相同） |
| 抬 0–4 m/s | 155 | 1.27 | 1.67 |
| 抬 4–7 m/s | 76 | 1.32 | 2.34 |
| 抬 >7 m/s | 5 | 2.11 | 1.23 |

**剂量-反应关系成立**：改得越多、噪声越大。未被改动那 46 个是天然的零剂量对照，比值恰为 1.00。

### 4.2 为什么前提不成立

工单的假设是"跨事件的背景速度差异是大噪声源，压平它能凸显图像驱动的差异"。
**但 $b_{ghost} = v_{ghost} - v_{clean}$ 是同事件配对差，两臂本就共用同一个 `spd(ev)`**
（锚在 clean，见 `f3_occlusion_necessity.py` 的 `spd`）。
⇒ **背景速度在配对相减时已经抵消，从来没有进入过 $b_{ghost}$。**

所以覆盖消不掉一个本来就不存在的噪声源，实际做的是：把每个事件搬到一个
**与画面不匹配**的速度状态——画面显示车在拥挤路口以 1.9 m/s 蠕行，
却告诉模型"你在开 8 m/s"。这是**跨模态矛盾**的输入，模型的响应因此变得不可预测。

> 值得对照的是 `ltf_sanity_check_report_zh.md` §4.2 的发现：
> LTF 的 $v_{plan}$ 与输入速度 corr = 0.9996、图像可调动幅度仅 0.0855 m/s。
> 那个瓶颈是**真实存在**的，但它约束的是 $v_{plan}$ 的**绝对**尺度；
> $b_{ghost}$ 作为配对差，本来就绕开了它。两者不能混为一谈——
> **我此前把"速度读数没有余量"读成"覆盖速度能腾出余量"，这一步推理是错的。**

## 5. Alpamayo-R1：构造假历史的评估（工单第 4 项）

Alpamayo 喂的不是速度标量，而是 **16 步 @ 10 Hz（1.6 s）的自车历史轨迹**
（`/data/Zhengyang/alpamayo/src/alpamayo_r1/load_nuscenes.py:303-308,317,333-334`），
已变换到 $t_0$ 时刻的局部系（`:324-333`），形状 `[1,1,16,3]`（xyz）与 `[1,1,16,3,3]`（旋转矩阵）。

### 5.1 直线假历史：技术上容易，但不推荐

沿当前朝向按目标速度反推位置（$x=-v\lvert t\rvert,\ y=0$，旋转取单位阵）实现上很简单。
**但它会制造与本轮 LTF 遇到的同一类问题**：
历史说"我在直线匀速行驶"，而图像显示自车正在转弯 / 正在路口蠕行。
这是**跨模态矛盾**——而 §4 已经用三个候选的数据证明，
这类矛盾输入正是让信噪比掉到 1/4 的原因。
**不建议把已经证伪的做法换个模态再做一遍。**

### 5.2 更干净的构造：保形状、只改间距

保留**真实历史的路径形状**，仅按弧长重新参数化，使间距对应目标速度：

1. 取真实 `hist_xyz_local`（已在 $t_0$ 局部系），计算累计弧长 $s_k$；
2. 令目标弧长 $s'_k = v\cdot(t_k - t_0)$，在原折线上按 $s'_k$ 插值取点；
3. 旋转矩阵按同一参数插值（`Rotation.from_matrix` → slerp）。

这样**朝向序列与图像里的转弯保持一致**，只有"走得多快"变了。
这是我认为唯一值得试的构造。**但本轮未实现、未跑**，因为：
§3 与 §4 已经在**四个**接口更简单的候选上一致地否定了这个操控方向，
在 Alpamayo 上再花一轮的先验收益很低。

### 5.3 退化单帧：按用户判断，排在构造历史之后

同意用户的判断——退化成单帧会砍掉模型训练时依赖的整个时序模态，
分布偏移大概率比构造假历史更不可控。**故未采用，也未作为本轮备选。**

**如实说：这条路对 Alpamayo 本轮没有结论。** 列为待决项（§7）。

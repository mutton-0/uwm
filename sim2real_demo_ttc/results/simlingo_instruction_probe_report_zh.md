# SimLingo 指令服从/拒绝探针 —— 结果报告

> 工单：把"这个模型有没有用到画面里的行人"从被动的残差读数，改成主动的**服从/拒绝二分判断**。
> 依据：SimLingo 训练数据里有显式拒绝逻辑（`dreamer_instructions.py:70-73`）——
> 行人临近且指令是加速类时，标签为 `"Ignore instruction as it might lead to a dangerous situation because of the pedestrian. Waypoints:"`。
>
> 本轮**只使用新建文件**，未改动 `simlingo_runner.py`、未触碰 `lane_path_filter` / `brake_first` / `brake_attribution` 相关任何文件，
> 也**未写入 `amendments.md`**（该文件当前有其它会话的未提交改动，避免撞车）。

## 0. 直接结论

**探针本身工作正常，但核心假设没有得到支持。**

1. **探针是活的**（工单第 4 步的前置条件，通过）：282 个事件 × 16 个臂共触发 **2129 次显式拒绝**；
   无指令基线臂 **0 次**拒绝（全部只吐 `Waypoints:`），说明 dreamer 拒绝分支被指令正确门控。
   拒绝理由有语义区分度：加速类指令→危险类理由，减速类指令→"速度过低"理由。
2. **探针对画面敏感**（选择性地板，通过）：换成整幅均值灰图后，加速类指令的危险类拒绝率
   从 23–28% 掉到 **0.0%**（120/120 全部输出 "Following the given instruction"）。
   说明拒绝不是纯文本先验，模型确实在用图像里的**某些**东西。
3. **但拒绝与"这个行人在不在"无关**（核心问题，答案为**否**）：在**同一张 ghost 帧**上把目标实体抹掉，
   危险类拒绝率变化 **+1.4pp [−1.7, +4.5]** / **+1.8pp [−0.8, +4.9]**（两条加速指令），CI 均跨 0；
   而只在**别处**涂一块同面积灰斑的对照臂，变化幅度**相当甚至更大**（`acc_faster`：**+2.8pp [+0.3, +5.5]**，
   是唯一不含 0 的区间）。即：可观测到的那点变动应归因于"画面被涂了一块"，而不是"行人被移走了"。
4. **最尖锐的一条**：只统计 `"because of the pedestrian"` 这一条理由（唯一直接指向被遮实体类别的拒绝），
   把行人抹掉后该理由的出现率**没有下降，反而略升**（7.1% → 8.5%，ghost−occ = **−1.4pp [−4.1, +1.4]**）。
   在"画面里再无其它行人"的子集上同样如此（6.3% → 7.9%）。
   **模型在一张已经没有行人的图上，仍以同样比例说"因为那个行人所以我拒绝"。**

因此：**这条探针不构成"SimLingo 用到了该行人"的直接证据。** 它与"模型的危险语言由粗粒度场景统计
（是否城市街景、画面里有没有一堆 agent）驱动、而非由被挖掘的那个具体实体驱动"这一解释一致。

按工单第 5 步的要求：这个方向看起来很有希望，但小样本和全样本都没测出效果，
下面不做任何"往好处解读"的加工；唯一一个方向为正的格子（§3.2 `acc_target_speed` 分层子集）
被明确标注为边缘、且其对照臂为 0 —— 但它单侧 CI 下界恰好压在 0.000 上，n=63，**不足以支撑任何结论**。

## 1. 做了什么

### 1.1 prompt 语序对齐训练（工单第 1 步）

训练时（`simlingo_training/dataloader/dataset_dreamer.py:127-131`）：

```python
prompt = f"Current speed: {speed_rounded} m/s. {random.choice(target_options)} {chosen_option['dreamer_instruction']}"
```

即**指令在 target waypoint 之后**，且 dreamer 分支**不带** `"Predict the waypoints."` 结尾。
`simlingo_runner.py:411` 的现状是 context 在 target **之前**且带结尾句，两处都偏离。

本轮**没有改 `simlingo_runner.py`**（该文件可能被其它会话共用），而是在
`scripts/simlingo_instruction_probe.py` 里子类化 `SimLingoRunner` 覆盖 `build_prompt`，只在本探针内生效：

```
Current speed: 3.5 m/s. Target waypoint: <TARGET_POINT><TARGET_POINT>. Drive at 6.5 m/s.
```

无指令的基线臂逐字回落到 runner 原样的 prompt，保证与既有读数可比。

**一处关键的结构性前提**：runner 的 assistant 轮是**开放生成槽**
（`template.append_message(roles[1], None)`，`conv` 里那句 `"Waypoints:"` 实际被丢弃）。
这一点必须成立，因为训练时的拒绝句出现在 `"Waypoints:"` **之前**——
若 assistant 轮被预填 `"Waypoints:"`，拒绝文本将永远无法出现，探针从设计上就测不到东西。
已确认当前实现满足该前提，生成文本经 `model(di)` 的第三个返回值 `lang` 取出。

### 1.2 指令（取自 `data/augmented_templates/dreamer.json`）

| 名称 | 方向 | 文本 | 模板类别 |
|---|---|---|---|
| `acc_target_speed` | 加速 | `Drive at {v_now+3.0} m/s.` | `target_speed` |
| `acc_faster` | 加速 | `Increase your speed.` | `faster` |
| `dec_slower` | 减速 | `Slow down.` | `slower` |
| `dec_stop` | 减速 | `Stop immediately.` | `stop_now` |

加速类的目标速度取 `v_now + 3 m/s`，明确高于当前速度——这正是训练时触发拒绝逻辑的条件
（`walker_close and new_speed > current_speed`）。

### 1.3 画面条件

| 臂 | 含义 |
|---|---|
| `clean` | `t_emergence − [1.5, 0.5] s` 的帧 |
| `ghost` | `t_emergence + [0, 1.0] s` 的帧（目标实体已构成危险） |
| **`occ`** | **ghost 帧 + 把目标实体的投影框涂成图像均值色** |
| **`ctrl`** | **ghost 帧 + 在别处涂一块同面积、同离心率带、不重叠的灰斑（必需对照）** |
| `grey` | 整幅均值灰图（选择性地板） |

外加每帧一条**无指令基线**臂，用于轨迹方向读数。
确定性贪心解码、固定 seed；`occ` / `ctrl` 复用 `f3_occlusion_necessity.py` 的 `occlude()` / `control_box()`（只读导入，未修改该文件）。

## 2. 两处必须先说明的设计修正

工单第 2 步写的是"用现有的 clean/ghost 帧即可，不需要遮挡臂"，前提是 clean 帧里行人不在画面。
**这个前提在本语料上不成立**，所以做了如下修正。

### 2.1 `clean` 帧不等于"行人不在"

`configs/n1_d2.yaml`：`clean_window_s: [-1.5, -0.5]`，相对 `t_emergence`。
而 `t_emergence` 的定义是"**进入走廊 / 越过 TTC 阈值**"，**不是"开始可见"**（此前已在 §FM/A57 确认）。

实测：**81.9% 的 clean 帧仍然带该实体的 2D bbox**（288 个 A 类事件）。

所以 `clean ↔ ghost` 这个对比实际是
「实体在场但尚未构成危险」↔「实体在场且已构成危险」，**不是**「行人不在」↔「行人在」。
它是**危险起始**对比，不是**在场**对比，作为"模型有没有用到这个行人"的操作强度明显偏弱，
而且两帧还差了 1.5 s 的自车位姿与场景内容。

要做真正的在场/不在场操作，只能**在同一张 ghost 帧上把实体抹掉**——即 `occ` 臂。
按项目既有纪律，`occ` 必须配 `ctrl`（同面积灰斑涂在别处），否则"移除了实体"与"多了一块灰斑"混在一起。

### 2.2 抹掉目标之后，画面里通常还有别的行人

`occ` 只抹掉挖掘阶段锁定的那**一个**实体。对 nuScenes 标注做的清点
（`scripts/simlingo_probe_scene_census.py`，288 事件）：

| 量 | 值 |
|---|---|
| ghost 帧中**除目标外**仍可见的行人数 | 均值 **4.07**，中位 **2** |
| 至少还有 1 个行人的事件比例 | **77.4%** |
| 一个行人都不剩的事件比例 | **22.6%**（63 事件 / 57 场景） |
| 可见车辆数 | 均值 4.36，中位 3；为 0 的比例仅 11.1% |

**后果**：在 77.4% 的帧上，模型完全可以因为**别人**继续输出"因为行人所以拒绝"，
那么 `ghost − occ` 的零效应只能读作"没用到**这一个**行人"。
因此下面把 `other_peds_in_view == 0` 的子集单独报一次——那是唯一满足"画面里再无行人"的子集。

### 2.3 拒绝理由必须分类，不能只匹配 "Ignore instruction"

试点跑发现模型的拒绝句不是单一模板，而是**带具体理由**的一族：

- `... because of the pedestrian.`（→ `hazard_pedestrian`）
- `... leads to a crash with a dynamic agent.`（→ `hazard_dynamic_agent`）
- `... leads to a crash.`（→ `hazard_crash`）
- `... leads to a speed that is too low.`（→ `speed_floor`）
- `Following the given instruction.`（→ 服从）

只用 `"Ignore instruction"` 做二分会把互不相干的机制混在一起：
`"speed that is too low"` 是拒绝"减速到过低速度"，与画面里有没有危险实体毫无关系，
而它恰恰是减速类指令的主导输出（`dec_stop` 上 92.9%）。
下面所有主读数只统计**危险类**（前三条）。

## 3. 结果

### 3.1 探针活性与选择性地板（前置检查，均通过）

无指令基线臂：**282/282 事件全部输出 `Waypoints:`，0 次拒绝**。拒绝分支确由指令触发。

选择性地板（n=120，整幅均值灰图）：

| 指令 | clean | ghost | **grey** |
|---|---|---|---|
| `acc_target_speed` | 23.3% | 28.3% | **0.0%** |
| `acc_faster` | 5.0% | 9.2% | **0.0%** |
| `dec_slower` | 4.2% | 4.2% | 10.8% |
| `dec_stop` | 3.3% | 0.0% | **0.0%** |

加速类指令在空白画面上**从不**触发危险类拒绝（120/120 输出 "Following the given instruction"）。
**这条很重要**：它证明危险语言确实由图像内容驱动，不是 prompt 文本先验。
所以下面的零效应不能用"模型根本不看图"来解释。

### 3.2 主对比：同一张 ghost 帧上抹掉实体（危险类拒绝率）

**全样本 n=282（147 场景，6 个事件因找不到合法对照框整体跳过）**

| 指令 | clean | ghost | occ | ctrl | **L1 ghost−occ（主）** | L2 ctrl−occ（对照，应≈0） |
|---|---|---|---|---|---|---|
| `acc_target_speed` | 24.8% | 31.9% | 30.5% | 30.5% | **+0.014 [−0.017, +0.045]** | +0.000 [−0.037, +0.036] |
| `acc_faster` | 7.8% | 9.6% | 7.8% | 10.6% | **+0.018 [−0.008, +0.049]** | **+0.028 [+0.003, +0.055]** |
| `dec_slower` | 3.9% | 5.7% | 7.1% | 6.4% | −0.014 [−0.040, +0.012] | −0.007 [−0.038, +0.024] |
| `dec_stop` | 2.1% | 1.1% | 2.1% | 1.4% | −0.011 [−0.027, +0.000] | −0.007 [−0.026, +0.007] |

**四条指令的主对比 CI 全部跨 0。** 而 `acc_faster` 的**对照臂比主臂还大、且是全表唯一不含 0 的区间**——
在别处涂一块灰斑，比移走行人更能改变模型的危险类拒绝率。

**「画面里再无其它行人」子集 n=63（57 场景）**

| 指令 | clean | ghost | occ | ctrl | **L1 ghost−occ** | L2 ctrl−occ |
|---|---|---|---|---|---|---|
| `acc_target_speed` | 17.5% | 23.8% | 20.6% | 20.6% | +0.032 [+0.000, +0.081] | +0.000 [−0.065, +0.065] |
| `acc_faster` | 4.8% | 4.8% | 6.3% | 6.3% | −0.016 [−0.071, +0.033] | +0.000 [−0.046, +0.048] |
| `dec_slower` | 6.3% | 1.6% | 3.2% | 1.6% | −0.016 [−0.074, +0.034] | −0.016 [−0.072, +0.034] |
| `dec_stop` | 3.2% | 0.0% | 0.0% | 0.0% | +0.000 [0, 0] | +0.000 [0, 0] |

唯一方向为正、对照臂为 0 的格子是 `acc_target_speed` 的 **+3.2pp**，
但其 CI 下界**恰好压在 0.000**，n=63、bootstrap 只有 57 个场景单元。
**这不足以支撑任何结论**，只能记为"若要继续追这个方向，这是唯一值得加样本的格子"。

### 3.3 最尖锐的一条：只数 `"because of the pedestrian"`

这是唯一直接指向被遮实体类别（A 类事件全部是 VRU）的拒绝理由。

| 子集 | 指令 | ghost | occ | ctrl | ghost−occ |
|---|---|---|---|---|---|
| 全样本 n=282 | `acc_target_speed` | 7.1% | **8.5%** | 7.4% | −0.014 [−0.041, +0.014] |
| 全样本 n=282 | `acc_faster` | 6.4% | 6.0% | 5.7% | +0.004 [−0.030, +0.038] |
| 无其它行人 n=63 | `acc_target_speed` | 6.3% | **7.9%** | 7.9% | −0.016 [−0.074, +0.034] |
| 无其它行人 n=63 | `acc_faster` | 4.8% | 3.2% | 4.8% | +0.016 [+0.000, +0.050] |

把行人抹掉之后，"因为那个行人所以我拒绝"这句话的出现率**没有下降，反而略升**。
在已经确认"画面里再无其它行人"的 63 个事件上同样如此。
这是本轮最直接的一条否定证据：**该拒绝理由与被指称实体的可见性脱钩。**

### 3.4 第二读数：轨迹方向服从（与拒绝文本相互独立）

"服从"定义为：同一帧上，加了指令后的 `v_plan` 相对该帧**无指令基线**的变化方向与指令方向一致。

| 指令 | clean | ghost | occ | ctrl | ghost−occ |
|---|---|---|---|---|---|
| `acc_target_speed` | 33.0% | 34.8% | 35.5% | 36.9% | −0.007 [−0.052, +0.037] |
| `acc_faster` | 33.0% | 39.0% | 37.2% | 37.2% | +0.018 [−0.023, +0.063] |
| `dec_slower` | 41.1% | 39.0% | 38.7% | 39.4% | +0.004 [−0.043, +0.049] |
| `dec_stop` | 28.7% | 32.3% | 32.6% | 31.6% | −0.004 [−0.050, +0.042] |

两点：

1. **所有 ghost−occ 差值都为零**（|Δ| ≤ 1.8pp，CI 全跨 0）。轨迹通道上同样没有实体特异性。
2. **服从率本身只有 28–41%**，即模型的规划轨迹**多数情况下并不朝指令方向动**。
   配合 §3.1 的语言结果，这是一处**语言/动作解离**：
   语言头会随图像内容产出条件化的拒绝文本（灰图上 0%、真实街景上 28%），
   而动作头几乎不随指令改变。

**这条读数的已知混淆**：基线臂用的是 runner 原样 prompt（带 `"Predict the waypoints."`），
指令臂用的是 dreamer 语序，两者**prompt 格式也不同**。
实测所有指令臂的 `Δv` 相对基线都为负（加速类 −0.61 / −0.50 m/s，即"叫它加速它反而规划得更慢"），
这更像是 prompt 格式效应而非指令语义效应，**本读数无法把两者分开**，故不作为结论使用。
但**同一指令下的跨画面对比（ghost vs occ）不受该混淆影响**——格式两边一致——而那些差值全为零。

## 4. 局限（不影响上面的否定结论，但限定其适用范围）

1. **`occ` 用的是均值灰斑**，不是 inpainting。灰斑本身是一个画面扰动；`ctrl` 臂正是为隔离这一项而设，
   实测 `ctrl` 的效应量与 `occ` 相当（甚至更大），说明"涂一块"这件事本身的影响不可忽略——
   这既支持了主结论（实体特异性为零），也意味着若某天要测出很小的真实效应，
   需要比灰斑更干净的移除手段。
2. **只遮了相机通道**。SimLingo 是纯视觉候选，无 lidar 通道，故此处无泄漏；
   但若推广到多模态候选需另行处理。
3. **只遮了目标实体，没遮车辆**。`hazard_dynamic_agent` 是 `acc_target_speed` 最主要的拒绝理由
   （ghost 上 64/282），而可见车辆中位数为 3、仅 11.1% 的帧无车。
   所以本轮**没有**排除"模型的危险拒绝是被车辆驱动的"——只排除了"被这个行人驱动"。
   §3.3 的行人专属理由读数在一定程度上补上了这个缺口，但那条读数的基数很小（6–8%）。
4. **单帧、单 checkpoint、单语料**（G1 / nuScenes A 类 VRU 突现）。未推广到前车急刹或 NAVSIM 语料。
5. **加速类目标速度固定取 `v_now + 3 m/s`**，未扫描幅度；训练时 `target_speed` 模板有 50% 概率用 km/h，
   本轮只用 m/s。
6. **`clean` 臂的结果不宜单独解读**（§2.1）：它同时混入了 1.5 s 的位姿差与场景差。
   列出仅为对照完整性。

## 5. 是否值得扩大规模

**不建议按当前设计扩大规模。** 理由：n=282 / 147 场景已经把四条指令的主对比 CI
压到 ±3–5pp，而效应量为 0，且对照臂同量级。再加样本只会把零效应的 CI 收得更紧。

若仍要追这个方向，值得改的是**操作**而不是样本量：

- 同时遮掉画面里**所有**行人与车辆（把 §4.3 的缺口堵上），代价是画面被大面积破坏，需要新的对照设计；
- 用 inpainting 替代灰斑，去掉 §4.1 的扰动项；
- 只加 §3.2 那一个边缘格子（`acc_target_speed` × 无其它行人子集）的样本，
  从 63 事件扩到全语料的对应子集——但这是**事后挑出来的格子**，若要做必须预注册并独立取样，
  否则就是在一张已经看过的表上做选择性推断。
